# Teams Webhook通知の文言ルール(2026-10-12制定)

すべてのWebhook通知(自動化スクリプト・launchdジョブ・対話中のClaudeセッション)はこのルールに従う。
目的は2つ: (1) 中村さんが件名だけで「対応が要るか」を判断できること、(2) 自動修復(WebhookAutoFix)が誤検知なくエラーだけを拾えること。

## 送り方
スクリプトからは直接curlせず、共通の送信口を使う(件名の整形、本文を1行に潰す処理、エラー時の修復キュー登録を自動で行う)。

| 言語 | 呼び方 |
|---|---|
| Python | `sys.path.insert(0, <notifyフォルダ>)` → `from teams_notify import notify` → `notify("ERROR", "ジョブ名", "要約", detail=..., log=...)` |
| bash/zsh | `source <notifyフォルダ>/teams_notify.sh` → `notify_teams ERROR "ジョブ名" "要約" "詳細" "ログパス"` |
| Node | `require('<notifyフォルダ>/teams_notify.js').notifyTeams('ERROR', 'ジョブ名', '要約', {detail, log})` |
| CLI | `python3 <notifyフォルダ>/teams_notify.py ERROR "ジョブ名" "要約" --detail ... --log ...` |

`<notifyフォルダ>` = `~/<Dropboxフォルダ>/中村正樹/.claude-sync/Scripts/notify/`
(個人Mac: `~/ICPTokyo2022 Dropbox/中村正樹/...`、会社Mac: `~/dentsuDropbox Dropbox/中村正樹/...`)
Webhook URLは各マシンの `~/.zshenv` の `TEAMS_WEBHOOK_URL` から読む。Dropbox上のファイルには書かない。

## 件名の形式
`[LEVEL] ジョブ名: 要約`

- **ジョブ名**: 毎回同じ固定の名前にする(例「Salesforce QBR DL」「メール同期」「HDY定点観測」)。自動修復は「ジョブ名＋要約」で重複を判定する。
- **件名の長さ**: Teamsのカードは件名が長いと途中で切れて表示される(2026-10-17、31字目以降が消えた)。**件名全体で28字以内**にする。ジョブ名は10字以内、要約は15字前後が目安。
- **要約**: 件数・状態など、事実だけを短く書く(例「成功0/失敗18」「ログインできず停止」)。詳しいことは本文(detail)へ。
- 送信口(teams_notify.py)は、28字を超える件名を自動で縮める: 長いジョブ名は `SHORT_JOB` の短縮名か10字で切り、要約は入るところまでで「…」。縮めたときは本文の先頭に「件名全文: …」を入れる。修復キューには元の件名が入る。新しいジョブ名が長くなるときは、`SHORT_JOB` に短縮名を足すか、最初から短い名前にする。

| LEVEL | 使う場面 | 自動修復 |
|---|---|---|
| `ERROR` | 自動化ジョブが失敗し、放置すると結果が出ない(リトライも尽きた) | **対象**(修復キューに積まれ、すぐに修復が起動する) |
| `WARN` | 一部失敗・一時的な失敗で、自動リトライの予定がある / しきい値に近い | 対象外 |
| `WAIT` | 人の操作・判断待ち(MFA承認、ログイン、課金判断、質問) | 対象外 |
| `OK` | 定期ジョブの正常完了報告 | 対象外 |
| `DONE` | 対話セッションのClaudeによる作業完了の報告 | 対象外 |
| `INFO` | 週次ダイジェスト、リマインドなどのお知らせ | 対象外 |
| `FIX` | 自動修復ランナーによる修復結果の報告(ランナー専用) | 対象外 |

迷ったときの判断:
- 人が動かないと直らない(MFA・ログイン切れなど)場合は `WAIT`。ただし、ジョブ側からはログイン切れかどうか判別できないなら `ERROR` にする。修復側が見て、人の対応が必要なら「要ユーザー対応」と返す。
- リトライ予定の途中経過は `WARN`、最終的に失敗が残ったら `ERROR`。

## 本文(detail)
- 1件ずつ「何が・どう失敗したか」を書く(失敗したレポート名とエラーメッセージなど)。改行してよい(送信口が「 / 」区切りの1行にまとめる)。
- `ERROR`/`WARN` ではログファイルのパスを必ず `log=` に渡す。スクリプトのパスは自動で付く。
- ホスト名と時刻は送信口が付けるので、本文に書かなくてよい。
- 社外秘の数値・個人情報・パスワード・トークンを本文に入れない(Teamsに残り、修復キュー経由でClaudeにも渡るため)。

## 例
```
[ERROR] Salesforce QBR DL: 成功0/失敗18
  本文: 月別見込（設定売総 X 部署）: レポートビルダーのiframeが見つかりません / ... / ログ: ~/SalesforceExport/.../run.log / スクリプト: ... / ホスト: d14461 / 10-08 09:46
[WARN] Salesforce QBR DL: 失敗3件を再実行予定
[WAIT] Salesforce QBR DL: Authenticator承認をお願いします
[OK] メール同期: 新着42件
[DONE] Nidec資料: 正本へ反映完了
```

## 対話セッションのClaude
CLAUDE.mdの「質問時・完了時にTeams通知」ルールで送る通知も、件名を `[WAIT] 〜` / `[DONE] 〜` で始める(`send_teams` を直接使う場合も同じ)。
こうしておけば自動修復が誤検知しない。対話セッションから `[ERROR]` は送らない(その場で直す)。

## 移行状況
タグのない旧形式の通知も、当面は自動修復側が件名のキーワードで判定する。これは会社Mac専用のスクリプトやPower Automateのクラウドフローから来る通知を拾うための後方互換で、移行が済んだら外す。
