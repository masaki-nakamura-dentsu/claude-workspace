## 実施内容
1. ナレッジベースの実データ量を精査した結果、`knowledge_untagged_01.md`(74.6万語)と
   `cases_apac_01.md`(55.6万語、検索回数16回で最多、Acecook Vietnam案件CASE_ID 7133を含む
   ファイル)が突出して巨大と判明。既に分離済みだった`cases_global_01.md`(40.8万語)・
   `case_expert_index.md`(9.9万語)と合わせ、計4ファイル(約185万語)を新規データセット
   「GBC Knowledge Pack - CASES (large files)」に集約(Claude実施)。
2. Difyのチャットフローに2つ目の「知識検索2」ノードを追加(中村さんの依頼でClaudeが実施)。
   ナレッジベース=上記新データセット、クエリテキスト=テンプレートの結合クエリ(既存の
   知識検索と同一)に設定。
3. **重要な技術的発見**: LLMノードの「コンテキスト」欄は1つの知識検索結果(Array[Object]型)
   しかバインドできず、単純に2つ目を追加すると1つ目が消える(既知の制約)。かつ、
   Array[Object]型はSYSTEM prompt本文への直接のインライン変数埋め込み({x}ボタンの
   候補一覧)にも出てこない(String/Array[String]等の型のみインライン挿入可能)。
   → 正しい解法は**「変数集約器」ノード**を知識検索と知識検索2の間に挟み、両方の
   `result`を1つのarray[object]に統合し、その出力をLLMの「コンテキスト」欄に
   バインドし直すこと。この配線は中村さん自身が実施(スクリーンショットで確認)。
4. SYSTEM prompt末尾に「大容量データセット側の結果も必ず確認せよ」という補足セクションを
   追記(Claude実施、クリップボード貼り付け方式)。

## 作業中に発生した2件の事故(データ損失なし、教訓として記録)
- **事故1**: contenteditable内で「/」を含むテキストをタイプすると、Difyのスラッシュ
  コマンド機能が発動し、続く文字列を飲み込んで意図しない変数チップ(コンテキスト等)が
  挿入される。→ 以後はテキスト本文の追記は「クリップボードへのペースト」方式
  (キー入力を伴わない)に切替えて解決。文中で「/」を使う言い回しも避けるよう修正
  (例: "CASES/KNOWLEDGE" → "CASES and KNOWLEDGE")。
- **事故2**: ポップアップをEscapeで閉じた直後、フォーカスがテキスト編集ではなくノード
  選択状態に戻っており、続けてBackspaceを押したためLLMノード自体が削除される事故が
  発生。直後にCmd+Zで復元、内容は無事(直前の保存ポイントまで戻っただけでデータ破損なし)。
  → 教訓: contenteditable内での編集後は、次のキー操作の前に必ずカーソルが本当に
  テキスト内にあるか確認すること。ノード削除は取り返しがつきにくいため特に注意。
- 総括: Difyのcontenteditableプロンプトエディタでの「文末へ確実に移動する」操作は
  `Cmd+A`→`ArrowRight`(選択を末尾に収束させる)が唯一安定して機能した。`Control+End`/
  `Meta+ArrowDown`はこのエディタでは効かない。
