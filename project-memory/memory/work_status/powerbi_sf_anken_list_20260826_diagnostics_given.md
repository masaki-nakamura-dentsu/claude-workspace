## 2026-08-26 セッション: SF案件リスト水増し問題、原因をレポート層に特定 → 最終的に2問題とも解決

**Status: done**

前回(8/25)からの続き。未解決問題1(`Raw YTD`2026年合計の約310万円水増し)を診断クエリで段階的に切り分けた。

**診断の流れと結果**:
1. `SF案件リスト`自体の重複チェック → 総行数5,281=ユニーク案件ID数5,281、重複ゼロ(クリーン)。
2. `Raw YTD`2026年分の`受発注ヘッダNo`重複チェック → 多数の重複グループを検出(件数2〜4)。
3. 重複行の詳細を展開 → **案件ID/クライアント名/部署名/市場は完全一致、`売上総利益`のみ異なる値**と判明。検算すると診断②の合計と一致(例: -195378+390756-88124+44062=151316)。**これはCASの正規の会計明細(元計上+訂正/戻し等)が同一`受発注ヘッダNo`の下に複数存在する、元から正常な構造**と判明。ファンアウト仮説は却下。
4. `Raw YTD`テーブル自体の2026年合計を直接算出(`List.Sum`) → **215,633,242円 = 8/21確定値と完全一致**。

**結論**: `Raw YTD`テーブル(Power Queryのデータ層)は完全に健全。水増しはPower Query側ではなく**レポートのビジュアルまたはモデルのリレーションシップ層**で起きている。8/25セッションで記録した「市場_Bridge/事業区分_Bridge/地域_Bridgeの自動検出による不要な直接リレーションシップ」(3〜4回再発した既知パターン)が再発している可能性が高いと判断し、次はユーザーにモデルビューでリレーションシップ一覧の確認を依頼。

**続き(セッション終盤)**: モデルビューのリレーションシップ確認では「Bridge」検索が0件ヒットしたが、Japan選択で実際に絞り込みが機能することを確認し、リレーションシップ自体は生きていると判断(検索UIの表示不具合と結論)。テーブルビジュアルの値フィールドはΣ(生列)であることも確認済みだったため、最終的に「フィルター」ペインを深く掘り下げたところ、**「部署名が(空白)ではない」という基本フィルター**を発見。空欄部署行(Salesforce未突合のCAS計上分)の合計がネットでマイナス(約▲210万円)だったため、除外フィルターにより表示合計が真の合計より大きくなっていたことが判明。フィルターを「すべて」に戻し215,633,242円と一致、**問題1解決**。

続けて**問題2(売総ランキングチャートのスライサー不反応)**にも着手・解決: `市場一致`/`事業区分一致`の詳細フィルター(=1)がテーブルにのみ設定されておりグラフに未適用だったことが原因、グラフにも追加して解決。派生タスクとして横棒グラフの上位N(既定20件)の表示件数拡大が次回持ち越し。
