# PowerBI GBC dashboard: 売上総利益実績ズレ調査 + openpyxlキャッシュ破損の横展開

## 2026-07-27T(session end)
Status: done
What: Power BIの「予算達成トラッキング」ページで売上総利益の実績(計上済)が208,553,147円とTableau/元Excel(197,446,224円)でズレていた件を調査。Tableauの.twbファイルをXMLとして直接読んでロジックを確認し、3つの仮説(ネイティブな重複ヘッダー、データの陳腐化、PowerBI再更新失敗)を排除した上で、真因を`CAS_SF_Crosstable`クエリの重複削除が(受発注ヘッダNo., 案件ID)のペア単位になっていたことと特定(5件のヘッダーが2〜3件の案件IDを持つため merge時にファンアウトし、2026年で32行・11,106,923円分過剰計上)。ユーザーが`Table.Distinct`を受発注ヘッダNo.単独キーに変更して修正・確認済み(診断用メジャー/クエリはまだ削除待ち)。
続けて別件で、Tableau `5. QBR_貢献見込 V1.0.twb`のクライアント別確度別チャートで1位のクライアント名が「9.88131e-324」という異常値になる不具合を調査。当初は「Listシートのクライアント名(調整後)が未入力」と誤診断したが、ユーザーが実際にExcelで開いて全部値が入っていることを指摘してくれたおかげで訂正: 実際は`クライアント名（調整後）`列が`=SUBSTITUTE(SUBSTITUTE(ASC(...)...)`という数式で、xlsxファイル内の数式キャッシュ値(`<v>`)が空になっていた(1,033件全部)。ファイルのdocProps/app.xmlに`Application: Microsoft Excel Compatible / Openpyxl 3.1.5`、`lastModifiedBy: ＡＩ コンシェルジュ Concierge Ai`、`modified: 2026-07-27T02:35:48Z`と記録があり、当日別の自動化ツール(AIコンシェルジュ)がopenpyxlでこのファイルを保存し、既知の「openpyxl数式キャッシュ破損」バグ([[openpyxl_empty_v_tag_corruption]])を再発させたことが根本原因と判明。TableauのExcel-directコネクタはExcelのようにライブ再計算せずキャッシュ値を読むため、NULLフォールバックの連鎖で巨大な"名前なし"グループが生成され、そのラベルが「9.88131e-324」という浮動小数点ゴミ値として描画された。
ユーザーがExcelで開いて上書き保存(Cmd+S)して即解決を確認。ついでに`QBR作成`フォルダ内の全xlsxファイル(19個)を数式キャッシュ欠落率でスキャンし、`Prep_SalesforceAllRecord.xlsx`(19%)、`GBC CAS実績_FY22 TO DATE.xlsx`のRaw YTDシート(9%、但し売上総利益等の金額列自体は5911件中1件のみ欠落で実害僅少)、`Prep_CAS X SF Crosstable.xlsx`のCheckシート(100%)等でも同じ破損を発見。ユーザーが全部Excelで開いて再保存し対応完了。本日はこれで終了、続きは別チャットで。
Next: 次回セッション開始時は、(a) CAS_SF_Crosstable修正に伴う診断用の一時クエリ/メジャー削除がまだ残っている、(b) 予算達成トラッキングページの本番KPIカードでの最終見た目確認がまだ、(c) 「AIコンシェルジュ」という別の自動化ツールがこのQBR作成フォルダ内のxlsxファイルをopenpyxl/Excel Online経由で編集しており、今後も同種のキャッシュ破損を再発させる可能性がある点をユーザーと要相談、を確認すること。
