## 2026-08-11T12:00:00 (推定)
Status: done
What: ユーザー指示によりClaude自身が専用Chrome(CDPポート9228、d14461とは別アカウント/別プロファイル)を使いPower Automateの「GBC出張申請登録」フローを直接編集・保存完了。実施内容: (1) 編集前に全体をzipバックアップ(~/PowerAutomateBackups/)。(2) 旧「開始して承認を待機」(Start and wait)を削除し、「承認を作成」(Create an approval, assignedTo=variables('承認者'))+ 並列3分岐に再構成: ①元の「条件」(承認/却下時の通知ロジック、For eachで情報共有先に一斉送信)、②新規「開始して承認を待機」(Wait for an approval completion、旧アクションと同名で作成し直すことで手打ち参照 outputs('開始して承認を待機')を復旧)→変数「承認完了」をtrueに設定、③Do-untilリマインドループ(遅延24時間→条件1で土日判定→平日のみ「リマインドメール送信」アクションで承認者宛にメール送信、ループ停止条件=承認完了ならtrue、タイムアウトP30D)。(3) 実施中に原因不明のストレイブロック(実行1→選択1→条件1/条件2→メールの送信(V2)2エラー→別のDo until)が出現、ユーザーに確認したところ「何もしていない、直して」との指示でDo untilノード削除により一括解消。(4) 保存時に2つの深刻な問題を発見・修正: (a) Power Automateの条件式ビルダーでは関数式を直接テキスト入力すると評価式でなく文字列リテラルとして保存される既知の罠(→[[power_automate_gotchas]]に追加検討)、fxアイコンの式エディタ経由で"@"プレフィックス付き評価式として正しく保存し解決。(b) 元「条件」アクションのrunAfterが「承認の作成」のみになっており「開始して承認を待機」と並列実行される構造的バグ(For eachのforeachソース選択が'前のステップから出力を選択します'必須エラーで無効に)を発見、設定タブの「この後に実行する」でrunAfter依存先を「開始して承認を待機」に変更して解消(承認/却下通知が承認完了を待たず実行されるレースコンディションを修正)。(c) Do-untilのタイムアウトP60Dがワークフロー全体の存続期間上限30日を超えるエラーが発生、P30Dに変更して解消。最終的に「フローを開始する準備ができました」の成功メッセージで保存完了、エラー・警告ゼロ。
