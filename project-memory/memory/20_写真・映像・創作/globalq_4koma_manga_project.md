- 目的: 広告会社の社員にグローバルビジネス/海外案件の勘所を、笑いながら学んでもらう社内向け4コマ漫画(Global Q掲載)

## 制作フロー(2段階)
1. **構成作成**: ChatGPTの「構成作家GPT」(カスタムGPT)にネタを渡し、STEP1(人が読む構成)→ユーザーが「OK」と言ったらSTEP2(JSON構成)を出力させる運用。ただしClaude Codeとの対話で既に十分練られた構成がある場合、この中間GPTステップは省略可能(2026-08-24に実際に省略し、Claudeが直接JSON+画像生成プロンプトを作成した)。
2. **画像生成**: GeminiのカスタムGem「Global Q 4コマ漫画制作」に、①テンプレート.jpg(4コマレイアウトの絶対基準・青枠のみ編集可)②ポスター画像(絵柄基準)③キャラクターPNG(各キャラの外見基準)を添付した状態で、シーン指示(構図・セリフ・演出)を渡して生成させる。JSON形式である必要はなく、Gemのシステム指示は「4番目の参照=シーン指示」として自然文/構造化テキストを想定している。

## 4コマの型(このGemの固定ルール)
- 起(1コマ目): 状況提示+違和感の種まき、まだ大事故にしない
- 承(2コマ目): ポカ夫の善意の行動でズレ・混乱を悪化・加速させる(単なる状況維持は禁止)
- 転(3コマ目): 一気にトラブル化、混乱を最大まで可視化。2コマ目からの因果関係を明確に
- 結(4コマ目): 麗子が短く本質を回収。説明・解説コマにしない、絵と一言で伝える

## 締めの言葉(各話の最後に入れる文章)の型
過去3話+第10話で一貫している構成:
1. 事実・海外の慣習/実情の提示(1〜2文)
2. 「〜ことも」で注意点・落とし穴を提示
3. 学び・視点の提示
4. 「〜ですね」で締める短い一文
短い段落を空行で区切る形式。説教くさくならないよう、各段落は1〜2文以内に収める。

第10話の締め:
> 新聞を出稿したら、掲載紙を回収して日本へ送る。日本では当たり前に思えるこの作業も、海外では一筋縄ではいかないことがあります。
> 「掲載紙を取りに行くだけ」のはずが、まさか洪水に追いかけられることも。
> 現地ならではのリスクまで想像して、余裕を持って備える。これもグローバルビジネスの大事な視点ですね。

## JSON構成のアーカイブ方針
各話で使ったJSON構成(最終確定版)は、その回の完成品フォルダ内に `<話数+タイトル>_構成.json` の命名で保存する運用に変更(2026-08-24〜)。
- 保存済み: 010(`010掲載紙が流された/010掲載紙が届かない！_構成.json`)、009(`009会長は新入社員？/009社長より偉い人_構成.json`)、008(`008 そのお弁当は優しさ？/008 そのお弁当は優しさ？_構成.json`)
- ユーザーいわく「過去2つ(008・009)しか遡れなかった」とのことで、007以前のJSON原稿はもう手元に残っていない可能性が高い。今後見つかった場合のみ追加保存。

- 背景リサーチ: イラン(2010年、ペット関連広告を公式に全面禁止)、サウジアラビア(宗教警察が犬猫販売を禁止)、東南アジアのイスラム圏(シャーフィイー派で犬=不浄、実際に「子犬と遊ぶ子供」広告が炎上・撤退した実例あり)。第11話は東南アジアの実例をベースに採用。

- ストーリー上の工夫: 単なる「使っていい動物か確認しよう」ではなく、①1コマ目はクライアントからの依頼として明確に描く、②2コマ目はポカ夫の後押しで迷いなく海外展開を決める(はじめの逡巡セリフは矛盾を生むため排除)、③広告に登場する子犬を「マスコット」化してポカ夫・麗子と戯れさせる演出を全コマに継続登場させる、④結の麗子のセリフは「動物選定はNG」ではなく「この子(動物)自体は悪くない、国によって使える/使えないが違うだけ」というニュアンスに変更し、麗子が子犬を撫でながら語りかける形にした。この「マスコット化」演出は、今後も広告物・小道具が話の核になるネタで再利用できる技法として有効そうだった。
- JSON構成の拡張スキーマ(第11話で確立、第10話の`character_consistency`/`source_reference`をさらに発展): `template_compliance`(型・因果関係チェーン・ドリフト防止規則)、`character_consistency`、`mascot_puppy`(擬人化するオブジェクトの外見統一ルール+`count_rule`で頭数固定)、`source_reference`、各パネルの`asset_reuse`(同一ビジュアルを複数コマで再利用する指示)。今後のJSON雛形はこの第11話版をベースにするとよい。
- Gemini生成→フィードバック→JSON修正のループを3往復実施。具体的な不具合と対策は [[feedback_manga_natural_plot_logic]] の「吹き出しミスの派生パターン」セクションに集約。
- **未完了・引き継ぎ事項**: 漫画本体・リード文・まとめ文は完成済みだが、2026-09-02時点で本番フォルダ(`011可愛さは世界共通？/`)にJSON構成ファイルが未保存(過去話の`_構成.json`命名慣習が未適用)。旧セッションのスクラッチパスに保存していた版はセッション終了で消去済みの可能性が高く、必要なら次回改めて確認・再保存すること。

- **ChatGPT「構成作家GPT」のシステムプロンプトを本話の教訓を踏まえてアップデート済み**(2026-09-16)。主な変更: (1)4コマ目ルールを「麗子が本質を回収」から「教訓を言葉で回収しない、副産物オチ/的外れオチ/ボケツッコミオチ/エスカレーションオチのいずれかで着地」に変更、(2)麗子のキャラ説明から「本質を一言で回収する」を削除し「教訓を語らず笑いのオチを成立させる役」に修正、(3)NG事項に「麗子が教訓要約フレーズを言うこと」を追加、(4)STEP1出力形式に「4コマ目のみ:採用したオチのパターン」の記載を追加。次回作でこのアップデートが機能しているか要検証。
- **英語指示によるJSON精度向上を試験導入**: Gemini生成の指示追従精度(キャラの左右配置維持、吹き出しの発話者アンカー、小さいテキストの描画)を上げるため、JSONの構図・演出指示(scene/composition/visual_points等)を英語に、セリフ本文(dialogue.text)は日本語のまま、というハイブリッド形式を試した。過去の全編指示は日本語のみだった。効果はあったが完全ではなく、[[feedback_manga_natural_plot_logic]]に残る問題点あり。
- **リード文の書式に関する訂正**: 過去の理解では「リード文=空行なしの一続きの文章、締めのまとめ文章=空行区切りの4段落」という使い分けだったが、本話でユーザーは最終的にリード文も空行区切り(1〜2文ごとに改行)を採用した。今後はリード文も空行区切りで統一してよい(過去作のフォーマットに固執しない)。
