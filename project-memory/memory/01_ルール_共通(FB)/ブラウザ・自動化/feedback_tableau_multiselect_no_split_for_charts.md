Salesforceの複数選択リスト(セミコロン区切り、例: `GBCCompetitorsGroup__c`競合グループ、`GBCCountry__c`市場)をチャートの凡例/カテゴリ/グループとして使う場合、**Tableau側が実際にどう扱っているかを先に確認してから実装方式を選ぶこと**。

**Why**: [[powerbi_jci_pitch_status_chart]]のCompetitive Analysisページ(Q1 (5))移植で、スライサー用に作った分解済みブリッジテーブル(`Table.Split`でセミコロン展開、1案件が複数行になる)をそのままチャートの凡例に流用したところ、複数の競合グループが記載された案件の売上が各グループに二重カウントされ、合計が約1.4〜1.8倍に水増しされるバグを起こした。twbファイルの`<encoding attr='color' ...>`ブロックを確認すると、Tableauは実際には組み合わせ文字列(例:「WPP; Omnicom」)を**分解せず1つの独立したカテゴリとして扱っている**ことが判明。スライサー用途(選んだ値を含む案件を絞り込みたい)とチャート集計用途(値ごとに金額を積み上げたい)では、同じフィールドでも正しい実装方式が真逆になる。

**How to apply**: 複数選択リストのフィールドを新しいチャートに使う前に、
1. まずtwb内の該当ワークシートの`<encoding attr='color' field='...'>`ブロックをgrepし、bucket値がセミコロン区切りの組み合わせ文字列のまま1カテゴリになっているか確認する。
2. スライサー(絞り込み)用途 → 分解済みブリッジテーブル(既存の`地域_Bridge_JCI`等のパターン)を使う。
3. チャートの凡例/カテゴリ(金額の内訳表示)用途 → 分解せず生のフィールド値(nullは`IF(ISBLANK(...),...)`で安全化)をそのまま使う。リレーションシップが必要な場合も、生の値ベースの1:多ディメンションテーブルを別途作る(ブリッジテーブルを流用しない)。
4. 実装後は必ず合計値をTableau側の既知の目標値と突合し、水増しされていないか確認する([[feedback_verify_against_official_totals]]の一般則の具体例)。
