[[overseas_staff_list_sync_automation]]構築時、月1回しか更新されないSharePointファイルの取得を
最初から1時間おき(`StartInterval=3600`)のlaunchdジョブにしてしまい、後でユーザーから
「このリストは月1回しか更新されない。1時間毎は頻度が高すぎる。1週間に1回へ」と修正指示を受けた
(2026-09-03)。

**Why**: 「バックグラウンド処理でトークンは食わないから安全側に倒して頻繁にしておく」という判断は、
Claude Code側のトークンコストはゼロでも、(1)Teams通知等の副作用が無意味に頻発する、(2)不要な
OneDriveオンデマンドファイルの再ハッシュ計算やSharePoint側への読み取りアクセスが積み重なる、
(3)後で「なぜこんなに頻繁なのか」とユーザーに確認の手間をかけさせる、というコストがある。

**How to apply**: 新しい定期実行タスクを設計する際は、
- まずソースデータが実際にどのくらいの頻度で更新されるか(月次ファイル、週次レポート等)を確認し、
  それに合わせた間隔を最初の設計時点で選ぶ(安易にhourly/daily をデフォルトにしない)。
- 「取りこぼし防止のためやや高頻度に」という判断をする場合も、その理由(取りこぼしリスクの大きさ、
  検知の即時性がどれだけ重要か)を明示し、ユーザーに一言断ってから実装するとよい。
- 関連する後続処理(今回で言う[[overseas_staff_assignment_history]]の再生成)がある場合、同じ頻度で
  自動化するかどうかも合わせて設計時に検討する(今回は後から「同じタイミングで自動実行できるか」と
  追加依頼されたが、最初から候補として提示できるとより良かった)。
