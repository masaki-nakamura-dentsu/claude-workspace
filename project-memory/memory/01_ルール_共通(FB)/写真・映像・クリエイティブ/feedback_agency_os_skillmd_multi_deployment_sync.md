**Rule**: when adding or changing any rule, bucket reference, or Knowledge Pack file description in Agency OS's instruction document, apply the same change to every per-deployment variant, not just the one you happened to open first.

**Why**: on 2026-09-15, added a new Knowledge Pack file (`topic_expert_index.md`) and a new Requirement H to `GPT作業/SKILL.md` (the ChatGPT Skill version) only. Nakamura-san caught it: "Dify用にSKILL.mdは修正していたと思いますが、ChatGPTと同じSkil内容にしないほうが良いのでは？" — `GPT作業/SKILL_Dify.md` is a separate 640-line file (branched 2026-09-12) with substantial Dify-specific content (web search disabled, PPTX template disabled, a split large-file retrieval architecture, several fabrication-fix patches) that would have been silently discarded if the ChatGPT version's content had simply been copy-pasted into Dify's system prompt. Caught before deployment, but only because the user happened to remember the divergence — I did not check for it proactively.

**How to apply**: before editing anything under `GPT作業/` for this project, `ls` the directory first to see how many `SKILL*.md` variants currently exist (as of 2026-09-15: `SKILL.md` ChatGPT, `SKILL_Dify.md` Dify; check [[gbc_intelligence_engine_project]] for whether a GBC Business or other deployment has been added since). Apply each change as a parallel, deployment-aware patch — same rule/bucket addition, but preserve each file's own deployment-specific caveats and disclosures (e.g. Dify's "no web search" / "no PPTX template" notices) rather than overwriting one with the other's full content.

**Extended 2026-09-15 (same day, second incident): local files can also lag the live platform, not just lag each other.** Right after fixing the ChatGPT/Dify divergence above, pushed the (still-stale) local `SKILL_Dify.md` toward Dify and Nakamura-san pasted the *actual* current Dify system prompt for comparison — it had 3 pieces of content the local file never had: two "事前抽出" variable-injection blocks referencing specific Dify node IDs (`{{{#<id>.text#}}}`, wired directly in the Dify workflow builder, not written in any local file), plus two prose rules (a Markdown-code-block-wrapping caution, a "don't report 0 hits just because relevance score is low" rule) that someone had added directly in the Dify UI and never backported. **This is a three-way sync problem, not two-way**: `SKILL.md` (ChatGPT local copy) vs `SKILL_Dify.md` (Dify local copy) vs whatever is actually live in each platform's editor right now. Before pushing any local file to a live deployment, ask for (or fetch, e.g. via the ChatGPT Skill editor's own CodeMirror pane — see [[gbc_intelligence_engine_project]] 2026-09-15 for the Cmd+A/Cmd+C clipboard extraction method) the platform's *current* actual content and diff against the local file first; do not assume the local file is authoritative just because you edited it most recently.

**Refinement 2026-09-15 (same day, third addition — adding `global_department_index.md`/Requirement I): after bumping a shared marker like "Requirements A–H" to "A–I", `grep -n` for the OLD marker string across every deployment file before calling the edit done.** A stray old reference to "Client deliverable requirements A–H" survived in `SKILL_Dify.md`'s Section 10 (a PPTX-fallback explanatory sentence, not near any of the edit sites this session's targeted greps had been checking) and would have shipped inconsistent if a final full-file grep hadn't caught it. `SKILL_Dify_for_paste.md` is regenerated programmatically from `SKILL_Dify.md` (strip frontmatter + local-only HTML comment blocks) rather than hand-edited a third time — do this via script, not manual copy-paste, to avoid a fourth place the same drift could reappear.

**Refinement 2026-09-15 (same day, fourth finding — a live-test bug, not a sync bug, but same root cause: incomplete enumeration): when adding a brand-new bucket to `SKILL.md`/`SKILL_Dify.md`, the file itself has MULTIPLE separate places that enumerate "all buckets" and each must be updated — not just one.** Added `global_department_index.md`'s bucket description, its COMMON KNOWLEDGE TEST MODE bucket-list entry, the Withholding-rule mention, a per-source "how to use" bullet, and Requirement I — but missed the **"Mandatory internal search pattern" paragraph in Section 2**, the actual per-turn checklist that governs ordinary (non-test-mode) operation. Requirement I alone only fires once the model has already recognized an assignment as global-facing; without the bucket also being in this baseline checklist, a broad/early-stage brief ("ユニ・チャームの海外展開について相談したい") produced zero department mentions in live Dify testing, confirmed by Nakamura-san. **How to apply**: after adding a new bucket anywhere in `SKILL.md`, run `grep -n "applicable buckets\|Search across\|all of A–"` (or similar) across the whole file to find every enumeration site, not just the ones touched so far — COMMON KNOWLEDGE TEST MODE's list and Section 2's "Mandatory internal search pattern" list are two DIFFERENT lists that must both be updated, and it is easy to update one and forget the other since they read as redundant restatements rather than two sites needing the same edit.
