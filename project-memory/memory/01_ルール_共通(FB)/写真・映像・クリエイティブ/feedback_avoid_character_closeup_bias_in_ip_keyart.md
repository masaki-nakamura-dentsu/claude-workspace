Discovered 2026-08-07 during the Vietnam Blue Lock cross-promotion work (see `work_status/vietnam_anime_ip_cross_promotion_project.md`, 2026-08-07T02:00Z entry). The client asked for a 3-brand joint visual to represent the "Blue Lock" IP/world broadly, explicitly NOT centered on the protagonist Isagi Yoichi as an individual ("潔にこだわらない, コラボレーション先は作品としてのBlue Lock").

**Problem**: simply instructing "don't draw a specific character's face, use distant silhouettes only" was not enough. If the rest of the prompt still contained an action/hero-shot verb or framing cue (e.g. "疾走感あふれる" / "a dynamic sprinting moment"), the model reverted to a face-closeup of the series' most recognizable character (Isagi, number 11) — because that IS the dominant pattern in the training data for "Blue Lock key visual." This happened twice on the same prompt structure before being fixed.

**Fix that worked reliably**: restructure the sentence so the **grammatical subject of the composition is the environment/logo/object**, not a person — e.g. "施設を広角で見渡す構図。奥の壁に『BLUE LOCK』の巨大ロゴ...画面手前中央に大きなボール...ボールから光の軌跡が伸びる" (the facility/logo/ball are the subjects; people are only mentioned afterward as small distant background silhouettes). This produced a clean result on the first try for two separate directions. A version that kept "疾走感あふれる" as the leading framing device — even with the same "no face closeup" negative instruction appended — failed again.

**How to apply**: whenever generating "world/brand" key art for a licensed IP (not a specific character) via ChatGPT/Gemini image gen ([[chatgpt_web_automation]] / [[gemini_web_automation]]), write the prompt so environment/logo/prop is the sentence subject and any people are a subordinate clause described as small/distant. Avoid leading action verbs (sprint/dash/looming) that cue a hero-shot framing, even if paired with an explicit "no closeup" instruction — the negative instruction alone is not reliable against a strong training-data prior for that franchise's iconic key visual.

**Follow-up (2026-08-07, same project, opposite problem)**: later the client reversed course and *wanted* multiple named characters, real third-party products, and real corporate logos all together in one shot (a proper 3-brand joint ad). Pure text instructions failed repeatedly on both ChatGPT and Gemini — every attempt reverted to a generic "exciting match" or single-face hero-shot key visual, ignoring the specific characters/products/logos requested (tried 3+ times with increasingly explicit negative + positive instructions, no luck, also burned into ChatGPT's monthly advanced-feature usage cap in the process). **What actually worked**: attach the real product reference photos (the bike, the noodle package, the patch box — same files used for the packaging generations) to the prompt and instruct "make all N of these attached real products appear in this scene, each held by a different character." One shot, first try, correct on all counts (products, logos on the products, multiple distinguishable characters). Conclusion: for any composition that needs specific real-world products/brands rendered accurately and prominently, attaching reference images is not optional polish — it's the mechanism that actually anchors the output; text description alone is unreliable once the IP's training-data prior (a single iconic hero-shot pattern) is strong. Reuse this pattern (reference-image attachment) as the default whenever a generation needs to feature real branded products, not just as a fallback after text-only attempts fail.
