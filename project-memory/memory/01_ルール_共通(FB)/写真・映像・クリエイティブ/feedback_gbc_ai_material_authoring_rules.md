Stated explicitly 2026-09-03 after reviewing a first draft of a "ChatGPT活用講義" Artifact ([[ai_katsuyo_pj_weekly_tips]]) built for GBC's AI活用PJ. These rules apply to **any** internally-authored GBC AI活用PJ material (weekly Tips, lecture decks, demo scripts) — not just this one artifact.

## 1. No personal attribution on commentary — it's an org initiative
The draft styled tips/comments as quotes "from Nakamura" (badge + quote marks). Masaki's correction: "組織としてやっているので「中村から」というのは不要です。普通にコメントとして書いてよいです。" **How to apply**: write practical-advice callouts as plain organizational text (a neutral label like "ポイント" is fine), never as a personally-attributed quote, even when the underlying insight originally came from Masaki's own experience. Also avoid first-person framing like "駐在時代、私は…感じています" — rephrase as a plain declarative statement.

## 2. Don't scope-limit materials to one audience subgroup when the content applies broadly
The draft was titled/framed as "海外拠点向け" (for overseas offices) throughout (title, sidebar, cover copy, section labels). Masaki's correction: "海外拠点以外でも今のGBC局員も使えるTipsなので、「海外拠点向け」と限定しない。" The source material (a list of how overseas members use ChatGPT) is a legitimate *starting point/illustration*, but the deck's actual audience and framing should be all of GBC, not a subset. **How to apply**: when building a Tips/lecture deck from one group's usage patterns, keep concrete real examples (they add credibility — e.g. specific overseas pain points like "駐在員はサインをしないといけないが現地語で読む時間がない" are fine to keep as illustrative "現場の声"), but generalize the title, target-audience labels, and framing language so the deck doesn't read as exclusive to that subgroup. Real comparative data between subgroups (e.g. a usage-rate stat) can still be shown — it's motivating, not scope-limiting — as long as the surrounding text doesn't imply the lecture is *for* that subgroup only.

## 3. Never mention confidential/pre-launch internal project names in materials with any external-facing or broad-audience use
The draft referenced "Agent OS" (a dentsu-internal tool, not yet launched within the department) as a forward-looking hook. Masaki: "Agent OSはまだ機密情報なので言及しない。" **How to apply**: before including any internal tool/project name in a deck, check whether it has been publicly/departmentally announced yet. When in doubt, omit it — don't assume something mentioned to you in a work context is safe to put in a broadly-shared deliverable. See [[gbc_intelligence_engine_project]] and other in-flight internal tools for similar caution.

## 4. Explain unfamiliar platform features (Custom GPT, Projects) with concrete setup steps, not just the concept
Masaki: "カスタムGPTやProjectについて分かっていない人が多いので、その説明を追加。実際の設定方法の説明追加。" Many staff know ChatGPT only as a chat box and have never touched Custom GPTs or Projects. **How to apply**: when a technique in a Tips/lecture deck depends on a ChatGPT platform feature beyond plain chat, include a short "what it is" one-liner plus a numbered click-path (e.g. "左サイドバー「GPTを探索する」→右上「作成する」→Configureタブで指示を入力"), not just the feature name and a prompt example.

## 5. When a feature is really "just do the normal thing" (upload a photo, upload an audio file), say that plainly — don't make it sound like a separate mode to activate
The draft phrased two techniques in a way that implied extra steps: "契約書を写真のままVisionで読ませる" (sounded like a separate "Vision mode" distinct from just uploading a photo) and "音声認識(Whisper)でテキスト化" + "GPT-Liveの音声モード" (sounded like separate named tools/apps). Masaki's questions revealed the real confusion: "写真を撮ってアップロードと何が違うか分からない" / "普通にスマホで録音してアップロードしてはいけないのか？" / "GPT-Liveの音声モードとはどれのことなのか分からない". The truth in all three cases: there is no extra step — uploading the photo/audio file the normal way *is* the feature (Vision/Whisper run automatically on any uploaded image/audio), and "GPT-Live" is just the new name for the microphone icon / voice mode staff already know inside the ChatGPT app, not a separate app or mode to find. **How to apply**: for any AI capability that's actually invoked by an ordinary user action (attach a file, tap the mic they already know), lead with "there's no extra step — doing X the normal way already uses this" rather than naming the underlying model/technology first and making it sound like something separate to learn. Name the underlying tech (Vision, Whisper, GPT-Live) only as a secondary/parenthetical detail, not the headline of the instruction.

## 6. Only recommend automation tools actually usable at dentsu — don't default to generic SaaS examples (Zapier, Make, Google Sheets)
The draft's automation chapter recommended Zapier/Make + Google Sheets, which are common in generic "how to automate with ChatGPT" content online but **not officially usable at dentsu**. Masaki: "電通はGoogleシートなどはオフィシャルには使えないので、GoogleシートやZapier/makeも連携ができません。他にいい方法があれば紹介して欲しい。" The realistic alternative, grounded in what GBC already uses internally (see [[powerautomate_attendance_summary_project]], [[gbc_smart_kinmu_automation]], [[cas_setting_request_powerautomate_flow]], [[teams_webhook_powerautomate]]): **Power Automate** for the distribution/system-integration piece, **SharePoint/Excel Online** (Microsoft 365) instead of Google Sheets, and keep the AI-only piece (search/summarize) inside ChatGPT's own Scheduled Tasks so it never needs an unauthorized external connector at all. **How to apply**: before writing any "connect ChatGPT to X" automation example in a dentsu-internal deck, verify X is actually sanctioned for use at dentsu (generic AI-blog examples assume a Google/Zapier-centric stack that doesn't hold here) — default to Microsoft 365 + Power Automate as the dentsu-safe equivalent.

## 7. Correct contact names — no invented org structures
The draft referred people to "各拠点のAIアンバサダー" (a per-office AI ambassador), which does not exist. Masaki: "各拠点のAIアンバサダーというのは存在しないので、GBCの中村・赤羽・榎本に連絡するように伝えて下さい。" **How to apply**: the actual point of contact for GBC AI活用PJ questions is **中村・赤羽・榎本** (GBC) — use this, not [[ai_katsuyo_pj_ambassador]]'s per-department "AIアンバサダー" concept, which is a different (and separately still-forming, see that memory's 2026-08-18 kickoff notes) initiative and should not be conflated with "who do I ask about ChatGPT tips."

## Related pattern: prepare demo materials for live-taught content
When a deck like this will be *taught live* with demonstrations, Masaki asked for ready-to-use fictional demo materials matching each chapter's example (a fake client brief, past feedback history, contract draft, meeting minutes, translation sample, monthly data) rather than leaving the presenter to improvise inputs on the spot. **How to apply**: for any future lecture-style deck, proactively build a small set of realistic-but-fictional demo files (clearly marked as fictional/demo-only, ideally unified around one fictional client/scenario for narrative continuity across chapters) alongside the deck itself, saved in the same delivery folder.
