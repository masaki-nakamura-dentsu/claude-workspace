## 展開の不自然さを避ける
現地に絡むトラブルを描く際、「キャラクターをわざわざその用事のためだけに現地へ派遣する」展開は不自然と指摘された(2026-08-24、[[globalq_4koma_manga_project]]第10話制作時)。
**Why**: ユーザーいわく「現地に掲載紙を取りに行くのは不自然。たまたま出張していたポカ夫が確認に行くぐらいが良い」— 目的のためだけに動く行動より、既存の文脈(たまたまの出張)に理由を接続した方が自然に読める。
**How to apply**: 今後、キャラクターを普段いない場所/状況に置く展開を書く時は、「その専用の用事のために動かす」のではなく、「別の理由で元々そこにいた/その状況だった」という偶然性・既存文脈を先に用意してから事件を起こす。

## Gemini画像生成での吹き出しミス
Gemini(NanoBanana経由)でセリフ入りコマを生成すると、セリフの内容と吹き出しの向き先(どのキャラの発言か)がズレる、キャラクターの左右配置と発話順(右→左に読む)が矛盾する、という不具合が頻発した(2026-08-24、第10話初稿で発生)。
**Why**: プロンプトで「セリフ内容」だけを渡し、「どちらのキャラが右/左に位置するか」「吹き出しの尻尾がどちらを向くか」を明示しなかったため、モデルが独自に配置してしまった。
**How to apply**: 今後、GlobalQ4コマ漫画のシーン指示を作る際は、各コマごとに (1)キャラクターの左右の物理配置 (2)発話順(右→左) (3)「吹き出しの尻尾は必ず発言者本人の口元に向ける」という指示、を明示的にセットで書く。修正が必要な場合は生成済み画像を添付した上で「どのセリフが誰の発言に見えてしまっているか」を具体的に指摘して再生成させる。

## 吹き出しミスの派生パターン(2026-09-02、第11話制作時に追加発見)
上記の基本ルールを守っていても、以下のケースでは追加の明示指示がないと同種の誤読が起きる。

1. **画面外の発言者(電話・クライアント等)**: 「クライアントの声」を吹き出しだけで表現すると、Geminiがそれを目の前の人物(はじめ)の発言として描いてしまうことがあった。**対策**: 遠隔の発言者は必ずノートPC/モニター等の通話画面の中に「顔」を大きく描かせ、吹き出しの発生源をその顔の真上に固定する指示を入れる。声だけ・点線吹き出しだけでは不十分。
2. **左右配置と会話の主導権のズレ**: 「後押しする側」のキャラを、発話順だけ考えて逆側(左)に置くと、読者にとって会話の流れが不自然に見えるという指摘を受けた。**対策**: 発話順(右→左)だけでなく「誰が話を主導しているか」も加味して左右配置を決める(主導する側を右=先に読む側に置く)。
3. **シーン説明文がキャプションボックス化する**: JSONの`scene`に「翌朝の日本オフィス。」のような時制・場面転換の説明文を書くと、Geminiがそれをそのまま画像内のテキストキャプションボックスとして描画してしまった。**対策**: 場面転換を明示したい場合は`scene`の説明文と別に「画面上に説明キャプションボックスは一切表示しない、時間経過は表情・状況の変化のみで表現する」という否定形の指示を明示的に添える。
4. **マスコット的な小道具・動物が意図せず複数体に増える**: 広告に登場する子犬を「マスコット」としてキャラクターと戯れさせる演出を複数コマに跨って指示したところ、1コマ内に同じ子犬が2匹描かれてしまった。**対策**: 複数コマに跨って登場する非人間の要素(動物・マスコット等)には`count_rule`のような形で「全コマを通じて常に1体のみ」という頭数制約を明示的に書く。

## 吹き出しミスの派生パターン(2026-09-16、第12話「さぁ飛行機で帰ろう！」制作時に追加発見)

5. **左右配置は「前のコマと同じ」という指示だけでは維持されない**: キャラの左右配置をコマ間で固定したくても、「1コマ目と同じ配置で」のような参照的な指示ではGeminiが実際に入れ替えてしまうことが繰り返し起きた(3コマ目でだけ左右が反転する事故が複数回発生)。**対策**: 全コマ共通の`position_rule`をJSON冒頭に明記した上で、さらに各コマの`composition`内でも毎回「キャラAは右・体は左向き、キャラBは左・体は右向き」と体の向きまで含めて独立して明示する(前のコマへの参照だけに頼らない)。
6. **小さいテキスト要素はGeminiに描画されずに欠落しやすい**: スマホ画面や搭乗券に「小さく」表示する指示をした固有名詞(空港名等)が、生成画像では単純に描かれない、もしくは意味のない重複表示になることが頻発した。**対策**: 重要な文字情報は「小さく隠す」演出を狙わず、搭乗券・案内板・地図ピンなど構造化されたUI/オブジェクトの中に、通常サイズの太字キャプションとして配置する。実際に安定して描画できた成功パターンは「AIRPORT A (current)」「AIRPORT B (correct)」のような、名称+括弧書き注釈を1行で完結させる形式。2行に分けたラベル(例:小さい注釈行+大きい本文行)は片方が欠落・重複しやすい。
7. **3人以上が登場するコマで、動作をしているキャラにセリフが誤帰属する**: 発言者として指定していないキャラが、笑顔でギフトを開ける等の能動的な仕草をしていると、Geminiがそのキャラの発言だとみなして吹き出しを付けてしまう(逆に発言者として指定した方が無言になる)ケースが複数回再発した。**対策**: 発言しないキャラには「口を閉じ、能動的な動作をしない、視線をそらす」等の明示的な非発言指示を書き、発言するキャラの吹き出しは「その人物の頭の真上・体の中心線上」など位置を強く縛る。3人登場するコマ(4コマ目の起承転結の「結」等)は2人登場のコマよりも誤帰属が起きやすいと想定して、特に念入りに指定する。

## ストーリー構成上の教訓(2026-09-16追加)
4コマ目で「女性上司(麗子)が本質を一言で回収する」という型を文字通り守ると、内容が正しくても「勉強漫画っぽい」("教育っぽい")とユーザーから指摘された([[globalq_4koma_manga_project]]第12話)。
**Why**: 麗子のセリフが教訓の要約(「〜が大事」「〜に気をつけて」等)になると、笑いより説教として読まれてしまう。
**How to apply**: 4コマ目は教訓を言葉にせず、(a)3コマ目のトラブルの副産物をビジネス用語等とのギャップで笑いにする「副産物オチ」、(b)本質と無関係などうでもいい点に反応する「的外れオチ」、(c)ボケ・ツッコミのやり取りで終わる「ボケツッコミオチ」、(d)「次はもっと厄介な状況が待っている」ことを匂わせる「エスカレーションオチ」、のいずれかで着地させる。教訓・学びの言語化は漫画本編ではなく、別枠の締めのまとめ文章側でのみ行う。この方針はChatGPT側の「構成作家GPT」システムプロンプトにも反映済み。

## Gemini Gemの画像生成の挙動(2026-10-07、第13話)
- Gem「Global Q 4コマ漫画制作」は**新規チャットの初回メッセージでは画像生成を拒否/テキスト化することがある**(「画像生成は対応外」「お役に立てません」)。同日の最初のチャットは、参照画像を添付した初回メッセージ→「この場で生成して」という追い指示で画像が出た。
- 同じチャット内で「1コマ目の小道具だけ差し替えて」と頼むと、直前の画像をほぼ複製して変更を無視することが2回続いた。部分的な差し替えは、ユーザーがPhotoshopで直すか、ユーザー自身がGem上で操作する方が早い。
- 2回以上やり直すと吹き出しの文字が毎回違う形で崩れる(「時間時間」→「完成祝め祝い」)。文字の修正はユーザーが自分で行う方針(2026-10-07明言)。

## テーマの伝え方(2026-10-08、第13話から)
- ユーザーは、テーマ(例:サマータイム)が**一目で分かる直接的な小道具**を好む。カレンダーの日付や小さな「SUMMER TIME ENDS」のような控えめな伏線は「分かりにくい」とされ、大きな注意ポスター「サマータイム終了注意！」に変えた。タイトルにもテーマ名をそのまま入れる。
- 「転」のコマは、出来事が起きた瞬間の突然さ(集中線・効果音・フラッシュ)をはっきり描く方を好む(3コマ目は「画面が突然つながった」演出をユーザーが追加指示)。
- 季節の話題は、掲載時期に合わせる(10月なら秋のサマータイム終了の向きで組む)。
- Geminiの自動生成がうまくいかない時は、ユーザー自身がGemを操作し、文字はPhotoshopで直す。Claudeは修正版の構成JSONを全文で渡す役に回る。
