[[kpi0909_bd_zenendo_jisseki_error_20260910]]の続き。BD部門の「前年度」表示を一時的に874,332,100(同僚のExcel値)に合わせるため、`貢献実績_前年合計`メジューの値がBDの正しい値(667,237,100)と一致することだけを根拠に「このメジューがこの列の実体」と推測し、新規TEMPメジューを作ってビジュアルに差し替えるよう指示した。しかし実際に差し替えた結果、BD以外の列(今年度実績・A・前年比の整合性)まで崩れた——値が一致することは、そのメジューが実際にそのビジュアルのその列にバインドされている証拠にはならない(たまたま同じ値になる集計ロジックが複数存在しうる)。

**教訓**: PowerBIのビジュアルのフィールド差し替えを指示する前に、可能なら`.pbix`を展開して該当ページの`visual.json`(`Report/definition/pages/*/visuals/*/visual.json`)を直接読み、`queryState.Values.projections[].field.Measure.Property`で実際に使われているメジュー名を確認してから指示すること。ただし**pbixファイルはDesktop/Serviceで保存されるまでディスク上の内容が更新されない**ため、ユーザーが今まさに編集中の未保存状態は見えない——この場合は無理に憶測で進めず、ユーザーにフィールドペインのスクリーンショットを求める方が安全。

このKPI表(今年度実績/前年同期実績/A/B/実AB/C/実ABC/前年度/前年比)は`前年実績_該当年実績+見込案件比較`ページの「前年案件ランキング」ビジュアルとは別物で、まだ正確なページ/ビジュアルを特定できていない(次回このレポートを触るときの持ち越し課題)。[[feedback_token_conscious_powerbi]]の「DAX助言に軸足」方針とも整合——実際に画面を見ながら作業するのはユーザー、Claudeは確認済みの情報でのみ指示を出す。
