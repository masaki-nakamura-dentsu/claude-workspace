2026-09-17〜18、Agency OS全体像PPTX(役員向け説明資料)を作成・レビューした際に中村さんから確認が取れた、役員限定資料に特有の2つの判断基準。[[feedback_gbc_ai_material_authoring_rules]](GBC AI活用PJの週次Tips・講義資料など**広く配布する**資料のルール)とは対象読者が違うため、逆方向の判断になる点に注意。

## 1. 役員限定資料では実クライアント名・詳細情報の開示はOK
Agency OSの活用イメージスライドに実クライアント名(Acecook Vietnam、ユニ・チャーム)入りの実際のやりとり例を掲載し、さらに実際のChatGPT共有リンクURL(社内ログイン必須、契約交渉の詳細全文が見える)まで貼ることについて中村さんに確認したところ「開示OKです」と即答だった。

**Why**: [[feedback_gbc_ai_material_authoring_rules]]の「機密プロジェクト名は言及しない」原則は、局内全体・PoC参加者など**広い/不特定の社内オーディエンス**向け資料が前提。役員限定で閲覧者が明確に絞られる説明資料は、実例の説得力(「実際にこのクライアントで使われた」という証拠力)の方が優先される。

**How to apply**: 資料の対象読者が「役員限定」「特定の少人数」など明確に絞られている場合は、実クライアント名・実際のやりとり詳細・社内限定URLの掲載を既定の選択肢として提案してよい(架空クライアントへの置き換えを自動的に持ち出さない)。ただし対象読者が「局内全体」「PoC参加者全員」等の広い/不特定多数になる資料では、引き続き[[feedback_gbc_ai_material_authoring_rules]]の匿名化方針を適用すること。判断に迷う場合は今回のように一度確認を取るのが安全。

## 2. 役員限定資料では注意書き・補足キャプションは省略してよい
作成したPPTXには「Knowledge Packの各プラットフォームへの反映は手動アップロード」「Web検索は蓄積データを経由せずその場検索」「両プラットフォームとも社内PoC運用中」といった注意書き(9-11pt相当の小さい補足キャプション)を図解の下に入れていたが、中村さんがこれらを全て削除して「注意書きは役員にはあまり意味がない」と明言した。

**Why**: [[feedback_maintain_current_state_doc_for_long_projects]]的な「現状スナップショット文書」(実務者が確認作業に使う社内ドキュメント)では、既知の制約・未検証事項を明記する誠実さが重要。しかし役員向けの説明資料は目的が違い、意思決定に必要な全体像・価値提案を簡潔に伝えることが優先され、運用上の細かい制約(手動反映である等)は本筋を薄める情報になる。

**How to apply**: 役員向け説明資料を作る際は、図解ごとに「※」で始まる注意書き・補足キャプションをデフォルトで入れない方向で下書きするか、入れる場合も最小限に留める。技術的な制約・PoC状況などは本文の主要メッセージ(例: 概要スライドの「社内PoC運用中」バッジ1箇所)に集約し、個々の図解に繰り返し注記しない。実務者向け資料(現状スナップショット文書、SKILL.md等)では引き続き注意書きを省略しないこと — この省略ルールは役員向け説明資料に限定した判断。
