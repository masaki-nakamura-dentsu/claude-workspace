When a fact about the origin/provenance of the user's own working methods or frameworks is true but could read as awkward or unnecessary if stated explicitly in a document meant for others (e.g. an internal 企画書), don't include it — even if it's an interesting or well-sourced finding.

**Why:** On 2026-08-04, while building the AI審査員プロジェクト企画書 and researching [[hakuhodo_proposal_analysis]], the research uncovered that the user's own "リボン思考"/"3ファクト+解釈" framework (see [[proposal_writing_framework]]) traces back to the user having personally found and adopted Hakuhodo OB(須藤亮)'s "リボンフレーム" and 宮井弘之's "黄金の方程式" from public research. This was correctly identified and confirmed, but the user then explicitly said not to state in the 企画書 document that "リボンフレーム is not dentsu's" — it wasn't necessary to spell out.

**How to apply:** Keep the accurate provenance fact in memory (so it isn't misattributed elsewhere, e.g. don't call リボン思考 "dentsu's own framework" when discussing competitive analysis), but when writing user-facing or shareable documents (企画書, decks, etc.), don't proactively surface the "this isn't actually [X]'s own idea" framing about the user's personal methods — just use the framework/structural similarity without the self-referential origin critique. If structural similarity to a competitor's method is worth noting for analytical value, phrase it neutrally (e.g. "structurally similar to") rather than as a statement about what does/doesn't belong to the user's own organization.
