pptxファイルを修正する際、python-pptxで毎回テンプレートから`Presentation(template_path)`で全スライドを再構築するやり方は、ユーザーがPowerPoint上で直接加えた手動修正(文言調整、箇条書きマークの削除、日付追加など)を跡形もなく消してしまう。

**Why:** 写真塾78回目の講座資料制作(2026-07-25)で、ユーザーが「私の方で修正しています」と言った後に、テンプレートから全面再構築するスクリプトを再実行してしまい、手動修正(まとめスライドへの日付・場所追加など)が失われた。ユーザーから「私の修正がもとに戻ってしまっていた」と指摘されて発覚。

**How to apply:** 二回目以降の修正依頼では、必ず対象の最新pptxファイル(ユーザーが保存し直した最新版であることを確認)を`Presentation(existing_file_path)`で読み込み、変更対象のスライド/シェイプだけを操作する(テキスト差し替え、スライド追加/削除/移動、画像差し替えなど)。テンプレートから作り直すのは、そのファイルがまだユーザーに一度も渡っておらず手動編集も加わっていない、真っさらな初回生成のときだけ。

関連: [[feedback_pptx_filename_versioning]]

補足(技術メモ): python-pptxでスライドの削除(`sldIdLst`からの`remove`+`part.drop_rel`)と順序入れ替え(`move_slide`: remove→insert)を同一スクリプト内で複数回行うと、まれにスライドが複製されたり別のスライドが消失したりする不具合が起きた(原因未特定)。複数のスライド追加・削除・移動を行った後は、必ず`shp.image.sha1`などで全スライドの画像ハッシュを比較して重複がないか、スライド枚数が意図した数と一致するかを検証してから完了報告すること。

**再発(2026-07-30、[[rakumaro_hcmc_rakugo_project]])**: セッション間でscratchpad内のビルドスクリプトが消えていたため、「スクリプトを最新pptxから再構築する」というアプローチを取った。テキスト内容はpython-pptxで全シェイプのtext_frame.textを比較して一致させたが、**図形の位置・サイズ(left/top/width/height)は比較していなかった**。その結果、ユーザーがPowerPoint上で以前修正していた表紙の師匠写真の位置がスクリプトの古い座標(高さ指定のみ・正方形画像で右端がスライド幅を1.3in超過)に戻ってしまい、「写真が右にズレてしまっている」と再度指摘を受けた。LibreOffice書き出しのPDFプレビューはスライド範囲外にはみ出した図形をクリップして表示するため、目視確認でも発覚しなかった。

**教訓の追加**: スクリプトが失われて再構築が必要な場合でも、可能な限り「最新のpptxファイルを`Presentation(existing_path)`で開いて対象シェイプだけ差し替える」を優先する。やむを得ずスクリプトから全再生成する場合は、テキスト一致に加えて全`shape`の`left+width <= slide_width`・`top+height <= slide_height`を機械的に検証し、元ファイルの座標ともなるべく突き合わせてから保存すること。
