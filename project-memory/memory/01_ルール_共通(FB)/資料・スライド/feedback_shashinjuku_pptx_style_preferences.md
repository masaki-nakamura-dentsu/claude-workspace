写真塾(モスクワ発、日本メンバーも半数参加)の講座資料をClaude Codeで作るときの、確認済みのユーザーの好み。

**企画の進め方**
- 次回講座のテーマを考える前に、過去回のアーカイブ(`Photographer/モスクワ本部データ/写真塾オリジナル/`、全77回超)を精読し、既出テーマの傾向・未着手の切り口を洗い出してから提案する。
- 前回の内容を踏まえた「続編」になっていることが多い。前回スライドの実際の内容(スライド枚数・構成パターン)も踏まえて構成を考える。
- テーマは初心者にも分かりやすい言葉に言い換える(例:「補色」は初心者に難しいので「カラフル(複数の色を1枚に集める)」に変更、という指示があった)。
- 実在の人物・具体的なエピソードを実例として盛り込むのを好む(友人の「毎日富士山」写真展、YouTuberドリキンさんの「5撮」など、ユーザー自身が知っている実例を提案してくる)。

**デザイン仕様**
- テンプレートは `Photographer/書類フォーマット/写真塾テンプレートv3.potx` を使う(.potxはpython-pptxで直接開けないので`[Content_Types].xml`のcontent-typeを書き換えてpptx化する)。
- 過去資料の実測値に合わせる: キーカラーはテーマaccent1の`#CC0066`、フォントはメイリオ(テーマのfontScheme自体を書き換える)、本文18pt/タイトル24pt程度、キーワードは`**word**`のようなマークアップから太字+キーカラーに変換して強調。
- アニメーションも過去資料と同じ「フェード(entrance)」を、段落ごとに最初は自動・以降はクリックで逐次表示、という仕様で付与する(lxmlでXML直書きが必要、python-pptx標準APIにはない)。
- 写真は大きく見せたいという要望が強い。作例は1枚の合成JPEGコラージュではなく、**個別のPictureシェイプ**でグリッド配置し、`crop_left/right/top/bottom`でセンタークロップ相当のトリミングを設定 — ユーザーが後でPowerPoint上のトリミング機能で範囲調整できるようにする。
- 作例スライド(写真グリッドのみ)には、右下に半透明の黒背景+白文字太字で「①色の縛り ― 赤」のような小さいラベルを入れ、写真の邪魔にならない形で「何の実例か」を示す。
- 1つの縛り/テーマの中に複数のバリエーション(色の縛りなら赤/カラフル/モノクロ、機材の縛りなら50mm/400mmなど)がある場合は、作例を1枚にまとめず**バリエーションごとに別々の作例スライド**に分ける。

**画像生成AI**: Gemini(NanoBanana)・OpenAIともAPI課金上限で自動生成できないことが多い(2026-07時点)。その場合はプロンプト文をスライドに仮置きするか、ユーザー自身がNanoBanana等で生成した画像を後日フォルダに納品してもらい、それを差し込む運用になる。

**ファイル運用**: [[feedback_pptx_edit_existing_not_rebuild]](二回目以降の修正は既存ファイルを直接開いて部分編集、テンプレートから作り直さない)と[[feedback_pptx_filename_versioning]](同日修正は`_01`,`_02`...)を必ず守る。保存後は`open`で即座に開いて見せる。

**開催後の正式アーカイブ命名規則(2026-09-27確認、79回「撮影のマナーと法律2026」で確定)**: 講座本番が終わり、ユーザーが内容を確定させたら(またはユーザーから依頼があれば)、作業フォルダ(`Photographer/2026/<開催日>写真塾/`)のファイルとは別に、以下2箇所に正式版を保存する。
- **PPTX本体**: `Photographer/モスクワ本部データ/写真塾オリジナル/<N>_写真塾_<テーマ>.pptx` — `<N>`は全期間通しの連番(日付は付けない)。次の回を作る前に必ずこのフォルダをlsして最新の番号を確認し、+1した番号を使う(79回時点の最新は79）。
- **PDF(配布用、当日欠席者向け)**: `Photographer/モスクワ本部データ/写真塾資料/<YYYYMMDD>_写真塾_<テーマ>.pdf` — こちらは連番でなく開催日(YYYYMMDD)を使う。
- PDFは写真を多く含むため肥大化しやすい。保存前に`~/Scripts/pdf_shrink.py`で圧縮すること。デフォルト100dpiでも大きく残る場合は、[[pdf_shrink_tool]]のデフォルトgs呼び出しに`-dAutoFilterColorImages=false -dColorImageFilter=/DCTEncode -dJPEGQ=55`(グレーも同様)を足すと画質を保ったままさらに縮む(79回では16.7MB→7.1MBまで削減、目視で劣化なし確認済み)。
- ユーザーが明示的に指示しなくても、今後はこの2箇所への保存・命名・圧縮をこちらから行ってよい(2026-09-27にユーザーから「学んで次回から処理して」と明示指示あり)。
