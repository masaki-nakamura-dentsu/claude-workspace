「作った画面をそのまま説明時に使いたい」という用途では、通常のスクロール型ドキュメントではなく、章をクリックで進行させ、同じ章の中でも要素を少しずつ表示する「プレゼン形式」を作る([[chatgpt_token_saving_guide]]で2026-08-27に実施)。

**Why**: 説明者が話しながら操作するため、下の方の内容が先に見えてしまうと説明の順序が崩れる。また人が一度に処理できる情報量には限界があるため、同じ章でも一気に全部出すのではなく話す内容に合わせて小出しにしたい、というのがユーザーの明示的な要望。

**実装上の注意(はまった失敗)**: 最初の実装で、フラグメントを1つ表示するたびに`window.scrollTo(0,0)`していたため、「次へ」を押すたびに画面が先頭に戻り、説明のたびに毎回下までスクロールし直す羽目になった、とユーザーから指摘を受けた。修正: 章そのものが切り替わる時だけ先頭にスクロールし、同じ章内でフラグメントが増える時はスクロール位置を保持したまま新しく出た要素へ`scrollIntoView({behavior:"smooth", block:"nearest"})`で視線を送る、という実装にする。

**How to apply**: 今後「説明で使う」「プレゼンで見せる」目的のArtifactを作る際は、最初からこの2点を標準として組み込む — (a) 章単位でクリック進行、章内も要素を小出しにするフラグメント表示、(b) フラグメント表示ではスクロール位置を保持し章移動時のみ先頭に戻す。[[ai_katsuyo_pj_weekly_tips]]のような他の社内向けHTML Artifactでも、ライブ説明が想定される場合は同様の作りが有効な可能性がある。
