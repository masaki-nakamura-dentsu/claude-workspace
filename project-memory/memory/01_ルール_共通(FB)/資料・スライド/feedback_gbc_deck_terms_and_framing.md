- 用語は局内の言い方に合わせる: 「商談」ではなく「案件」。部の総称は「AP部・SP部・BD部」(「営業6部」は不自然)。拠点事業プロデュース部=BD部。「売総をつくる人」のような造語は使わない。
- 数字はCAS売総だけで見ない。貢献売総(グループ会社の支援を含む)も局のKPIで、規模はCAS売総の約5倍。分析・打ち手は両方で出す。
- SFの責任者の数字=その人の貢献ではない(先輩が責任者でスタッフとして動いた人は出てこない)。「売総ゼロの人」などと決めつけない。
- 上位の人が優秀とは限らない。大型案件は担当BPのクライアントが海外の相談を持ってくるかで決まる面がある(運)。そのうえで、大型の機会を自分から探す努力を打ち手にする。
- 他局の案件でGBCに数字が来ないものは、情報だけ入っていて何もしていない可能性が高い。「貢献が残っていない」と解釈しない。
- 提案・ピッチ用のJUはつくらない。各AP部は担当BP局を持っている前提で、若手向けに関係づくりの型を示す。

**Why:** 2026-10-21 GBC機会戦略資料のレビューでの指摘。
**How to apply:** GBCの数字・人・働き方の資料を作るとき、最初からこの用語と見方で書く。[[gbc_budget_predictability_analysis]]

## 追加(2026-10-21 2回目のレビュー)
- 「入口」→「戦略」、「機会」→「パイプライン」、「稼ぎ頭」→「扱い上位クライアント」。タイトルはシンプルに(「上位10社について」)。
- CASと貢献は混ぜない。前半CAS・後半貢献で同じフォーマット、ページ右上にラベル。冒頭にPower BI(KGI/KPIレポート定期保存PDF)の現状を貼る。
- 既にやっていること(貢献を部ごとに毎月追う、海外拠点の日系ピッチ情報の毎月受領、AP部の相談窓口、BX横断チーム・インバウンドチーム、Out-InはGBCが常に担う)を新しい打ち手として書かない。
- 提案の時期・手段には根拠を付ける(根拠のない「7〜9月」はNG)。因果を確かめずに「部をまたぐと取れる」と書かない。
- 貢献売総の数字は必ず最新(Power BIと一致)を使う。
