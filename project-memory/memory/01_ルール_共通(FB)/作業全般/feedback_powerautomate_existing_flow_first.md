Power Automateの自動化を拡張・修正してほしいと頼まれたとき、共有された1本のフローだけが全てだと思い込まず、**同じアカウント(共有アカウント含む)の他の既存フローが無いか先に確認する**こと。

**Why:** [[powerautomate_attendance_summary_project]]の作業で、共有された「戦略企画部_出退勤カード投稿」フロー(朝カード投稿のみ)だけを見て「ボタン応答を受信するフローが存在しない」と誤って結論づけ、Teamsの「誰かがアダプティブ カードに応答した場合」トリガーを1から組もうとして、Microsoft公式が既知の不具合として認めている「Something went wrong」エラーの壁に何度もぶつかった。しかし実際には、Teamsのスレッドに既に整形された応答メッセージが投稿されている実物の証拠(スクリーンショット)があり、そこから逆算して「戦略企画部_勤務状況Teams投稿」という別フローが既に存在し、しかも正常に稼働していることが判明した。もし最初に「他にフローはありますか？」と確認していれば、無駄な試行錯誤(新規トリガー構築の失敗、公式ドキュメント調査、代替アーキテクチャの検討)をほぼ全て省略できた。

**How to apply:** ユーザーから「今Power Automateでこういう運用をしている、これを拡張したい」と言われたら、共有された1本のエクスポートだけで全体像を把握したと思わず、早い段階で「対象アカウントのmake.powerautomate.comの『マイフロー』一覧に、関連しそうな名前の別フローがないか確認してください」と尋ねる。特に、実際の運用で「見えている挙動(例: 自動投稿されている整形メッセージ)」と「共有された設計」に矛盾がある場合は、即座にこの確認を挟む。
