大量の画像を読む作業(PDFページのレンダリング+Read、qlmanageサムネイル生成+Read、候補写真の多数枚比較など)はトークンを消費するため、着手前にユーザーに確認する。

**Why**: ユーザーから「画面キャプチャはトークンを使うので、画面キャプチャをする作業のときは確認して」と明示指摘(2026-08-27、[[subway_photo_booklet_project]]の見積もり更新作業中——確認用PDFの全10ページレンダリング+候補写真十数枚の目視突合を無確認で実行した)。

**How to apply**: 「PDFの各ページを画像化して目視確認する」「候補写真を何枚も開いて見比べる」「qlmanageでスライドを画像化する」等、画像読み込み(Read tool on image)を何度も伴うタスクに入る前に、必要性と枚数感を一言添えて確認を取る。1〜2枚程度の軽い確認(既存の[[feedback_pptx_visual_qa_method]]的な単発チェック)は許容範囲と考えられるが、「全ページ目視QA」「複数候補の突合」のようにまとまった枚数になる場合は特に注意。テキストベースで代替できる情報(pptxのテキスト抽出、ファイル名、EXIF等)があればそちらを優先し、画像を開く枚数を最小限に絞る。

より広い括りは[[feedback_token_conscious_practices]]参照(2026-08-31統合)。

**2026-10-05 追記(Nidec PPTX QA)**: 36枚デッキのQAで6枚ずつの高解像度シートを3枚読んだ時点で「画像を読み込んでいるようですがトークン消費大丈夫？」と指摘あり。以後は (1) 全スライドを低解像度(各700px程度)の1枚の一覧に結合して1回だけ見る、(2) 修正後は直したスライドだけ確認、を標準にする。LibreOfficeは游ゴシック等の日本語フォントを描画できない(d14461)ので、QAはqlmanageの1枚分割方式を最初から使う。
