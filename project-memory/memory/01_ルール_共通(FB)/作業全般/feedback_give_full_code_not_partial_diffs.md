2026-08-25、[[powerbi_migration_gbc_dashboard]]のSF案件リストSalesforce直結化作業中、正樹さんに対して「詳細エディターの末尾を以下に置き換えてください」と部分的なコード片だけを渡す指示を出したところ、正樹さんの操作(または過去のやり取りの積み重ね)で、渡した部分の**前にあるべき中間ステップ(レコードタイプ絞り込み・Account結合ロジック)が丸ごと消えてしまい**、存在しないステップ名を参照するエラーになった。この状態に気づかず次の指示を重ねてしまい、後から「全クエリのコードを見せてください」と確認して初めて発覚。結果的に同じ作業を何度もやり直す羽目になった。

**Why**: Claudeは会話の中でその外部システム(Power BI Service、Power Automateなど)の「今何が実際に保存されているか」を直接見ることができず、会話履歴から推測するしかない。特に同じオブジェクト(クエリ・フローなど)を複数ターンにわたって少しずつ編集させていくと、「今どの版が実際に保存されているか」がClaude側でもユーザー側でも曖昧になりやすい。「末尾/先頭を差し替えて」という指示は、両者が同じ「現在の全体」を正確に共有できている前提でしか安全に機能しない。

**How to apply**:
- 同じクエリ/フロー/設定に対して2回目以降の編集を指示する際は、原則として**そのオブジェクトの完全なコード・設定を丸ごと提示し、丸ごと置き換えさせる**。部分差分("末尾だけ""この2行だけ")での指示は、直前にそのユーザー自身が全文を見せてくれた直後(内容を正確に把握できている)場合に限り許容する。
- 特にPower Query M、Power Automateの式、DAXなど、外部ツールの詳細エディター上で編集される言語は、迷ったら「詳細エディターの中身を一度全部見せてください」と先に確認を求める方が、部分編集の指示を重ねて事故るより結果的に速い。
- 複雑な作業が難航し始めたら(同じような編集を3回以上繰り返している、エラーが連鎖している等)、一度全体のコードを確認してから続きの指示を出す習慣に切り替える。

**2026-09-01追記(派生パターン)**: [[powerbi_gbc_dashboard_current_state]]の`Salesforceデータ取得日時`クエリ修正で類似の事故。今回は「2回目以降の部分差分」ではなく、**1回目から現物を見ずに「中身を丸ごと置き換えてください」と全文コードを提示**したことが原因(元クエリが単純な`= DateTime.LocalNow()`ではなく`#table`でテキスト列化する構造だったのに、そのことを確認せず推測で書いた)。`Missing_References`エラーで発覚し、姉妹クエリ(`CAS実績データ最終更新日時`)の実コードを見せてもらって初めて正しい構造が分かった。**教訓の拡張**: 「丸ごと置き換え」を指示する時も、そのクエリの現在の中身を一度も見ていない(推測で書いている)場合は、提示前に「詳細エディターの中身を先に見せてください」と確認するか、少なくとも「見えていないので構造が違ったら教えてください、その場合は姉妹クエリ等を参考に再構成します」と留保を明示する。特にPower BIの「データ鮮度表示」系クエリ(このプロジェクトに複数存在)は`#table`でテキスト列化するのが標準パターンなので、次に類似クエリを触る時はこの構造を前提に組み立てること。

**2026-09-06追記(DAXメジューの「測定値名」欠落パターン)**: [[qbr_powerbi_tableau_verification_20260906]]でPower BI Service(ブラウザ版)のDAXメジュー編集中、`VAR SelectedYear = CALCULATE(...)`から始まる式(測定値名の代入`貢献実績_合計 = `を含まない、式本体だけ)を渡したところ、正樹さんが「既存メジューの中身を全選択して貼り付け」た際に**測定値名の行ごと消えて**しまい(既存の`貢献実績_合計 = `部分も含めて丸ごと置き換わるため)、`'VAR'の構文が正しくありません`エラーが2回連続で再現した。原因は式の先頭が偶然`VAR`だったこと自体ではなく、**渡したコードに測定値名の代入行が含まれていなかった**こと。**教訓**: Power BIのDAXメジューを丸ごと貼り替えさせる指示を出す時は、必ず`測定値名 = \n<式本体>`の形で、1行目に測定値名の代入を含めて渡すこと(式本体だけを渡さない)。これで再発なく解決した。

**2026-09-10再発**: [[qbr_powerbi_case_collision_investigation_20260910]]で`案件別ブレンド値`メジュー修正時、この教訓を知りながら再び測定値名の行を省略して式本体だけ渡してしまい、正樹さんから「教えてくれるときには必ず『案件別ブレンド値 = 』から作ってくれないとコピペに失敗する」と指摘を受けて再発が発覚。**教訓の強化**: この種の指示は記憶(過去の教訓)だけでは徹底されないことが実証されたので、Power BIのDAXメジュー全文を提示する直前に「1行目に`測定値名 = `を含めたか」を機械的にセルフチェックしてから出力する習慣にすること。
