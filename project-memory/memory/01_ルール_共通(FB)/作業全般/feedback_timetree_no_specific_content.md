TimeTreeカレンダーには、たとえユーザーが依頼メッセージ内で具体的な予定名(例:「澤本会」「下西さんおかえりなさい会」)を書いていても、その内容をそのままTimeTreeのイベントタイトルとして登録してはいけない。

**Why**: 2026-09-15、ユーザーから4件の会合(澤本会・下西さんおかえりなさい会・北村映画会・サンドアート演奏)をTimeTreeに登録するよう依頼され、個人カレンダーに具体名で登録したところ、後から「予定の中身を書くのはNGです」と訂正が入った。確認したところ、「既存の『父夜いない』だけで十分」とのことで、個人カレンダーに具体的な予定を作ること自体が不要——家族カレンダーの汎用フラグ(父夜いない/🍙父ランチいらない)のみで管理したいという方針。理由の詳細(プライバシー等)は語られていないが、依頼文に具体名が書かれていても額面通りに登録先の中身に反映してはいけない、という点が重要。

**How to apply**: 今後「TimeTreeに予定を登録して」と言われた場合、
- 家族カレンダー(JHwx6a86DdDo)向けの父夜いない/🍙父ランチいらないのような汎用フラグ登録はそのまま実行してよい。
- 個人的な会合・予定そのものを具体名でTimeTreeに書き込む依頼が来た場合は、実行前に「TimeTreeには汎用フラグのみでよいか、具体名を書いてよいか」を確認する。過去の依頼文に具体名があってもそれを鵜呑みにしない。
- 関連: [[timetree_web_automation]]（同日、終日フラグのトグルが実際には効いていなかったバグも発見・修正し、同ファイルに詳細を記録済み）。

**2026-09-21 追記**: 「TimeTreeに予定追加して」と依頼された際、対象日に既に汎用フラグ(父夜いない/🍙父ランチいらない)が登録済みだった場合は、ユーザーに確認を取らずに新規追加をスキップしてそのまま処理を完了してよい(「既に登録済みでした」の結果報告のみでよく、「どうしますか？」と聞き返す必要はない)。具体名での登録が必要なケースは、ユーザー側から明示的に指示があった時のみ行う——指示がない限りは常にこの汎用フラグルールで進めてよく、毎回「汎用フラグか具体名か」を聞き返す必要はない(このやり取り自体は初回の確認だけで十分、以後は既定動作として扱う)。

**2026-09-27 追記**: ユーザーの既定運用は「平日で父夜いないの日は🍙父ランチいらないもセット」(夜だけの例外日はユーザーが個別指定。例: 10/14・10/19は夜のみ)。夜フラグ追加依頼時は、ランチもセットにするか一言確認するか、既定でセット追加を提案すること。また夜予定の抜け漏れはOutlook exportに無い場合もある(10/13はexportに夜予定なしだがユーザー指摘で追加)。

**2026-09-27 追記(教訓)**: Outlook export(`~/CalendarExport/calendar_events.json`)を根拠に抜け漏れ判定する前に、`last_synced_from` のスナップショット日時で鮮度を確認すること。フローは毎日4:00実行なので最大約1日遅れ。今回はフローが週1設定だったため6日古く、10/13の夜予定を見落とした。
