Power Automateのフローをユーザー自身に画面操作してもらいながら組み立てる進め方(Claudeは直接デザイナーを操作できないため)で、明確に指摘・確認されたスタイル。

アクション名リネームが式の手打ち参照を壊す件など、Power Automateプラットフォーム自体の技術的な罠は[[power_automate_gotchas]]に集約したので、そちらを参照。ここは進め方(コミュニケーションスタイル)の話のみ。

## 値の入力方法を毎回明記する

各アクションの各フィールドについて、次の3パターンのどれで入力するかを**毎回**明示すること。
- 【通常入力】: 地の文と変数が混ざる場合。地の文はキーボードでそのまま入力し、変数は動的なコンテンツから挿入する(fxは使わない)
- 【動的コンテンツ】: 変数1つだけをそのまま使う場合。動的なコンテンツから選ぶだけ
- 【fx】: `if(...)`や`concat(...)`など関数を使う場合。数式モードに切り替えて式全体を入力

**Why:** [[powerautomate_attendance_summary_project]]の作業中、ユーザーが「これはFxに入れるのか、そのまま値のところに入れるのか」と明示的に質問し、「今後もどのように入れるかを忘れずに教えてください」と依頼した。入力方法を誤ると(例: 関数呼び出しの文字列をそのままテキストとして貼ってしまう)保存はできても実行時に意図通り動かない。

**How to apply:** Power Automateの値設定を指示するたび、上記3パターンのどれかを明記する。この会話に限らず、Power Automateのステップバイステップ指導全般に適用する。
