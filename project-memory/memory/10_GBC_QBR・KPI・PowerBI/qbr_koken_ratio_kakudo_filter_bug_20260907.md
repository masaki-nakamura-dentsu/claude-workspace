2026-09-07、正樹さんが`4. QBR_貢献実績 V1.0.twb`(Tableau)と`GBC数字管理レポート.pbix`(PowerBI)の「貢献度%」を突合したところ、2026年度Q1-Q3でTableau13.3% vs PowerBI22.2%、2025年度でPowerBI23.1%と大きく乖離しているのを発見。

## 原因
[[qbr_powerbi_tableau_verification_20260906]]の前日セッションで、`貢献実績`テーブルのPower Query「フィルター処理された行」ステップに部署フィルタと一緒に`[確度] = "A"`を誤って追加していた。これは`貢献度平均`メジュー(`DIVIDE(SUM(貢献売総_計上), SUM(Group売総))`)の**分母(Group売総)だけを圧縮**し、比率を約1.7倍に押し上げていた。分子(貢献売総_計上=実績計上額)は確度フィルタの有無で変化しないため、9/6の「金額の公式一致検証」では問題が表面化しなかった。

## 実データでの検証(`GBC 貢献実績_FY22 TO DATE.xlsx`)
2026年度1-9月: 全確度=13.29%(Tableau一致)、確度Aのみ=22.35%(PowerBI一致)。2025年度通年: 全確度=12.53%、確度Aのみ=23.08%(PowerBI一致)。重複確認/フェーズ/部署の3条件は現データでは実質無効(該当データが0件)であり、確度フィルタのみが乖離の原因と確定。

## 重要な訂正: 確度とGM承認の関係
[[powerbi_migration_gbc_dashboard_koken]]に記載していた「Att.Rev(計上)はGM承認だけで決まり確度とは無関係」は不正確だった。クロス集計の結果、確度=B/C/XでGM承認=Trueの行が29件(全期間)存在するが、その全てで計上額は0円。つまりこの列は実質的に「確度=A **かつ** GM承認=True」でのみ非ゼロになる。このため:
- 分子(貢献売総_計上)は確度フィルタの有無に関わらず不変 → 実績合計の検証だけでは今回のバグに気づけない
- 分母(Group売総、確度B/C/X＝未確定の見込み案件も含む想定総額)に確度=Aフィルタを掛けると、「年間想定規模に対する進捗率」から「確定案件内だけの計上率」に指標の意味自体が変わってしまう

**教訓**: 比率メジューの分母に使う集計列には、分子側の検証で使った同じフィルタ条件を安易に流用しない。分子と分母で「何を母集団とすべきか」が異なる場合があることを常に疑う。

## 修正の経緯と最終決定
1. 当初、`and [確度] = "A"`を削除(Tableau方式=全確度含む分母、13.3%/12.5%)で確定と考えた。
2. その後正樹さんが「元々のPowerBIの数字(22.35%=確度Aのみ)の方が正しい」と方針転換、`and [確度] = "A"`を復元する手順を案内。
3. Tableau側の`貢献度`計算フィールドも同じロジック(`SUM(...)/SUM(IF [確度]="A" THEN [Group売総...] END)`)に揃える提案をしたが、社内で再度議論した結果、**最終的にTableauの計算式(確度フィルタなし、全確度含む分母)を採用することに決定**。
4. PowerBI側`貢献実績`テーブルM式の`フィルター処理された行`ステップで`and [確度] = "A"`を**削除ではなくブロックコメント化**(`/* and [確度] = "A" */`)して無効化。正樹さんが2026-09-07に実施・確定済み。コメントとして残すことで、将来また同じ議論になった時にすぐ復元できるようにする意図とみられる。
5. Tableau側(file④)は元々確度フィルタが無かったため変更不要、これで両ツールの定義が一致した。

**最終結論(2026-09-07時点)**: 「貢献度%」は**全確度(A/B/C/X)含むGroup売総**を分母とする(=年間の想定ビジネス規模全体に対する進捗率)。確度Aだけに絞る計算は不採用。今後この指標に触れる時はこの定義で統一すること。
