# 背景

2026-09-08、方針変更により指標の呼称を「売上総利益、貢献利益」→「CAS売総、貢献利益」に統一したいという依頼。`~/Downloads/KGIKPI レポート (2).pbix`(Power BI Serviceのブラウザ上で作業しているものをダウンロードしたコピー)を解析。

**重要な発見**: ファイル内に「貢献利益」という文字列は一切存在しない。貢献側は既にメジュー・`指標選択`テーブルの値とも「貢献売総」で統一されていた。ユーザーに確認したところ、**貢献側は「貢献売総」のまま変更しない**、**Power BI Serviceブラウザのみで作業する**、との回答([[feedback_token_conscious_powerbi]]の通り本人が手を動かす前提)。

# 変更規模(pbixray + PBIR直読みで特定)

「売上総利益」という語が以下45箇所に渡って存在:
- 生列2個: `Raw YTD`テーブルの`売上総利益`列(Salesforce/Excelソースの`GBC CAS実績_FY22 TO DATE.xlsx`のRaw YTDシートの元ヘッダー名がそのまま列名になっている、Power Query側でのリネームステップは無し)、および**`CAS予算`テーブルにも別の独立した`売上総利益`列(Float64)が存在**(2026-09-09に手順書実施中の実エラーで判明・追記。当初`model.schema`を`Raw YTD`テーブルに絞って検索したため見落とした)。
- メジュー42個(うち11個は名前自体に「売上総利益」を含む=リネームが必要、31個は数式本文で`[売上総利益_合計]`等を参照しているだけ=本文修正のみで名前は変更不要)
- 計算テーブル`指標選択`の値1箇所(`{ "売上総利益", "売上", "原価", "貢献売総" }` という手入力の選択肢テーブルで、CAS/貢献の指標切り替えスライサーの元データ)
- レポート側は「用語定義集」ページを含め、視覚化のタイトル等への直書きは無い(全てフィールド参照経由なので、モデル側の名前変更だけで表示は自動追随する)。ただし「指標」スライサーを使っている7ページ(★予算達成トラッキング、★CAS_部別_月別、★CAS貢献売総_見込み整理、CAS_年別推移、CAS_月別_前年比、CAS_Q別前年比、CAS_前年実績_該当年実績+見込案件比較)は、`指標選択`テーブルの値変更後にスライサーの選択状態が無効になるため、再選択して保存し直す必要がある。

# 成果物

依存関係順に並べた完成形DAX(44箇所全て)を含む手順書を作成:
`Claude作業フォルダ/KGIKPIレポート_売上総利益リネーム/売上総利益→CAS売総_変更手順.md`

Phase1(列リネーム)→Phase2(基礎メジュー11個、依存順)→Phase3(指標選択テーブル)→Phase4(ハードコード文字列比較5個)→Phase5(参照のみメジュー31個)→Phase6(スライサー再選択7ページ)の順。Power BI Serviceの測定値編集がリネームを他の数式へ自動反映しない可能性を考慮し、全ての新DAXは新名称を書き込み済みの完成形で用意した(自動反映される挙動だった場合でも同じ内容なので害はない)。

**注意**: 実際のPower BI Service上でのリネーム操作自体はユーザーが行う(このセッションでは実施していない)。完了後は[[powerbi_gbc_dashboard_current_state]]の該当箇所(もしあれば)を更新すること。

**【2026-09-09 完了】** ユーザーがPhase 1〜7を全て実施し、リネーム自体は完了・確認済み。その後追加依頼: ★CAS_部別_月別ページで「貢献売総」に切り替えても数字が変わらない不具合を報告→原因は`指定指標_年別`メジューのSWITCH文に元々「貢献売総」分岐が無かったこと(リネーム作業とは無関係の既存の設計漏れ)。`貢献実績_合計`が市場/事業区分/地域とリレーションシップ経由で正しく連動する(TREATASでクライアント/組織名にも対応)ことを確認した上で、`指定指標_年別`のSWITCHに`"貢献売総", [貢献実績_合計]`分岐を追加する修正案を提示・適用依頼。**同じ欠落が`指定年の前年_動的`(CAS_Q別前年比・CAS_月別_前年比で使用)にもあるが、ユーザーの意向で今回は対象外**(将来必要になれば同じパターンで直せる: SWITCHに`"貢献売総", [貢献実績_前年合計]`を追加)。詳細は[[powerbi_gbc_dashboard_current_state]]にも反映済み。

**【2026-09-09追記・重要な訂正(リネーム作業中に発生)】** 当初「レポート側はフィールド参照経由なので名前変更だけで表示が自動追随する」と記載したが誤りだった。Phase 1〜6実施後、ユーザーから複数ページで「1つ以上のフィールドに問題があります」エラー(視覚化のフィールドウェルに旧メジュー名が⚠️付きで残る)の報告を受けた。**Power BI Service上でメジュー/列をリネームしても、既存の視覚化(カード・テーブル・コンボチャート等)のフィールドウェルの参照は自動更新されない**(Desktopのモデルビューでのリネームとは異なる挙動)。影響を受けたのはPhase2でリネームした11個のメジューを直接フィールドウェルで使っている11視覚化(CAS実績_案件別内訳/貢献実績_案件別内訳のテーブル・棒グラフ、CAS_年別推移/Q別前年比/月別前年比のカード・コンボチャート、★CAS貢献売総_見込み整理のカード×2・テーブル)。手順書にPhase 7として「名前変更対応表」+「修正が必要な視覚化一覧」を追記して対応(ユーザー自身がフィールド差し替えを実施)。**教訓は[[pbix_pbir_layout_parsing_technique]]に一般化して追記済み**: 今後同種のリネーム作業では、DAX参照だけでなく視覚化のフィールドウェル参照も別カテゴリとして必ず洗い出すこと。
