## 背景
「2026パイプライン 0910.xlsx」の`KPI0909`シート、貢献売総ブロック(A13〜)の「前年度実績」列(G15:G20)は数式ではなく手入力の固定値。BD部門(G18=874,332,100)がPower BIの数字(667.2M)と約2億円(207,095,000円、+31%)食い違っていることが発覚([[qbr_powerbi_tableau_verification_20260906]]、[[qbr_koken_ratio_kakudo_filter_bug_20260907]]、[[qbr_cas_combined_vs_rawytd_ap2sp1_gap_20260909]]の系譜の続き)。

## 原因
Salesforce一次データ(`GBC 貢献実績_FY22 TO DATE.xlsx`、Att.Rev(計上)ベース)と突合した結果、**BD部門以外(AP1/AP2/AP3/SP1/SP2)は完全に一致**、BDだけが667,237,100(正)に対し874,332,100(誤)と大きく乖離。以下を全て試したが874,332,100を再現するデータソースは見つからなかった:
- 9/6修正前のCOMBINED.xlsxスナップショット(Att.Rev(A)ベース)→ BD=667,237,100(修正後と同じ、乖離なし)
- Group売総(貢献前総額)ベース → 桁違い
- 会計年度(4月始まり)にずらした集計 → 合わない
- 商流(Business flow)の誤分類 → 該当区分自体が存在しない

**このワークブック内の過去のKPIシート(KPI0212→KPI0310→…→KPI0909、2026年2月〜9月の7ヶ月分)を遡ったところ、BD=874,332,100は最古の`KPI0212`(2026/2/12、当時のラベルは「25年度実績」)の時点から一度も変更されず、そのままコピーされ続けていた**。他部署の値も同様に2月から不変だが、こちらは現在のSalesforce一次データと一致するため問題なし。つまり2026年2月にこの参照テーブルを最初に作った時点で、BD部門だけ入力ミス(出所不明、古い/別集計のコピペと推測)があり、それが7ヶ月間誰にも再検証されずに複製され続けた。

## 結論
- Power BI側(667.2M)が正しい。今回のPower BI vs 同僚Excelの数字相違は、Power BI/Tableauの既知バグ系列([[qbr_powerbi_tableau_verification_20260906]]等)とは無関係で、**パイプライン管理xlsx側の古い固定値の入力ミス**が原因。
- 修正要: `2026パイプライン 0910.xlsx`の`KPI0909`シートG18(→874,332,100を667,237,100に)、G21(合計、2,521,231,714→約2,314,136,714に連動)。
- **教訓**: このworkbookの「前年度実績」列は数式ではなく毎回手入力/コピペで運用されており、一度入力ミスが起きると誰も気づかないまま何ヶ月も複製され続ける構造的リスクがある。次回同種の突合依頼が来たら、まずこの列が数式かどうか(＝最新データに追従しているか)を確認すること。

## 【確定】2026-09-11
正樹さんが同僚(BD部門の元データ作成者)に確認した結果、**Power BI側(667.2M)が正しく、同僚のExcel数字(874.3M)が誤りと判明**。上記「結論」の推測が裏付けられた。

**修正方針(2026-09-11、正樹さん指示)**: `2026パイプライン 0910.xlsx`のG18/G21は**今回Claude側では修正しない**。原因データを作成した同僚が次回更新時に自分で直す予定なので、正樹さん/Claude側から先回りして触らない。次にこのワークブックの関連セルを見る機会があっても、能動的に修正提案しない(向こうの更新を待つ)。もし何ヶ月後も未修正のままなら、その時点で改めて状況を確認してから判断する。
