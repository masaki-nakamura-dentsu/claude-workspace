## 仕組みの概要
GBCの「設定チーム」(荒川友宏、五十嵐長武、川嶋紗矢香、青山夏子)が運用する案件設定申請の仕組み。Microsoft Forms(CAS設定リクエスト)に局員が入力 → Power Automateフローが「新しい応答が送信されるとき」トリガーで起動 → 支払先①②③の情報を整形して設定チームへ通知メール送信(8分岐、見積添付の有無等で分岐)。

## 既知の不具合パターン: 「DIAS担当者名・メールアドレス」が自動返信メールで空欄になる
**2026-06-02時点**で既にこの項目(支払先①②③、Forms上の項目番号12/28/44)が「参照できず空になってしまっているかも」と報告され、中村正樹が修正。
**2026-08-21に再発**: 同じ症状(担当者が入力しても自動返信メールで空欄)が再度報告され、ユーザーがV4.1として修正を試みた版(`CAS設定リクエストV4.1_*.zip`)をエクスポートして確認依頼。

flow定義(definition.json)を解析した結果:
- メール本文中でDIAS担当者名・メールアドレスは支払先ごとに固有のFormsフィールドIDを参照: 支払先①=`r474328aa975247f3a946f25111d5c3c1`、②=`r90456d4343824df181fa057c0b3dc236`、③=`r0aef47b264aa4860b99c1d211070109c`。
- この参照は8つあるメール送信アクション(「メールの送信 (V2)」〜「_7」)すべてで完全に同一 → もし参照が古い(Forms側で質問編集により内部IDが再発行された)なら、**どの分岐でも一律に空欄になる**、という報告された症状と整合する。
- 静的なflowエクスポート(definition.json)には、フィールドIDと質問タイトルの対応表(スキーマ)は保存されていない(Power Automateデザイナーが動的コンテンツピッカーを開いた時にライブでコネクタから取得する情報のため)。よってエクスポートだけでは「このIDが今のFormsの質問と一致しているか」は判定不能。

**Why (推定原因)**: Microsoft Formsは質問を削除して再作成した場合(あるいは一部の編集操作)に内部質問IDを新規発行することがあり、Power Automate側の動的コンテンツ参照(rXXXXX)が古いIDを指したまま取り残される、という典型的な失敗モード。同じ項目が2回連続でこの症状を起こしている(6月・8月)ことから、Forms側の編集のたびにこの特定の質問だけが再発行されている可能性が高い。

## 宛先/BCC管理のSharePoint Excel化(2026-09-28完了)
[[profit_split_app_admin_cc_bug_fixed]]と同じ発想で、通知メールの宛先/BCCをフロー内ハードコードからSharePoint上のExcelテーブル参照に変更。

- **背景**: 荒川さんから「設定リクエストの通知メールから五十嵐さんを解除」「(利益配分依頼アプリの方は)川嶋さん・青山さんをデフォルトで追加」の依頼。利益配分依頼アプリ側は`GBC_アレココ - サイトドキュメント/設定関連/GBC利益スプリット管理表.xlsx`のDeptMasterシート「管理者」行(セミコロン区切りメール一覧)にgzc358(川嶋)を追加するだけで解決(青山=gzc408は既に登録済みだった)。CAS設定リクエスト側は初回はPower Automateフロー自体の編集が必要だった。
- **旧構成**: `変数を初期化する（宛先）`/`変数を初期化する（BCC）`という2つのInitialize Variableアクションにメールアドレスの固定文字列(セミコロン区切り)が直書きされており、8分岐すべての「メールの送信(V2)」がこの2変数を共通参照(`@variables('宛先')`/`@variables('BCC')`)する設計だった。五十嵐さん除外自体は「宛先」変数の値からその1アドレスを消すだけの1箇所修正で完了。
- **新構成**: 新規ファイル`設定関連/CAS設定リクエスト_通知先管理.xlsx`(テーブル名`NotifyList`、列: 種別[宛先/BCC]・名前・メールアドレス)を作成。フロー側は`GetNotify_宛先`/`GetNotify_BCC`(Excel Online (Business) 表内の行を一覧表示、フィルタークエリ`種別 eq '宛先'`/`種別 eq 'BCC'`)→ Apply to each → 文字列変数に追加(`concat(item()?['メールアドレス'], '; ')`)で「宛先」「BCC」変数を組み立てる方式に変更。今後の追加/削除はこのExcelを編集するだけで反映され、フローの編集は不要。
- **⚠️発見した実行時バグ**: このフローの環境では`join(select(...))`や`filter(...)`のような**高階関数(item()を使うコレクション関数)を「変数を初期化する」/「作成(Compose)」の値に直接書くと、構文・データが完全に正しくても実行時に`InvalidTemplate: The template function 'select'(または'filter') is not defined or not valid`で失敗する**という現象を確認(2026-09-28)。原因不明(構文・データともに検証済みで問題なし)。詳細と回避策は[[power_automate_gotchas]]に集約。回避策: Apply to each + 文字列変数に追加(`concat(item()?['列名'], '; ')`)のループ方式に置き換えることで解決した。
- **失敗通知**: このタイミングで、フロー詳細ページのベルアイコン(flowFailureAlertSubscribed)を有効化する手順も案内済み(実施はユーザー側、aiconアカウントでクリックする想定)。
- **荒川さんへの案内**: SharePoint「設定運用関連」ページ(`https://esq365.sharepoint.com/sites/GBCarekoko/SitePages/設定運用関連.aspx`)に「設定リクエストメール配信先設定」というリンクを追加し、NotifyListへ誘導済み。
