## Data-quality gotchas hit while extracting raw Salesforce exports from the pipeline workbook
- Each sheet (`...A0708`/`B0708`/`C0708`) has a trailing **`合計` (subtotal) row** at the bottom with garbage-looking values in the ratio/Group売総 columns (e.g. ratio=51.05) if naively included as a data row — always filter these out (detect via GBC案件ID column == `'合計'`) before summing. This row's own stated totals are actually a **useful cross-check**: it independently confirmed the raw per-row sum matches KPI0708's column values to within ~¥10,000 on ¥1.3B totals (rounding only).
- Raw export column schemas have an extra leading blank column + a mid-row blank spacer column not present in the `_Original` sheets' schema — needed explicit index-mapping (drop specific 0-based indices) to align, not a straight 1:1 copy.
- ~26 raw forecast rows (14 unique 案件ID) had blank クライアント — the live formula's fallback (`XLOOKUP` against an external-linked "List - Project" table, keyed by 案件名 not 案件ID) wasn't replicated at first; user supplied the correct client names for these deals afterward (see below).

## IMPORTANT: two different, incompatible "確度A" conventions across files — do not assume consistency
This caused several rounds of back-and-forth and a wrong "double-counting bug" diagnosis before the user clarified. Record this clearly for any future work touching these files:

- **山本さんの`2026パイプライン 0708.xlsx` (and its raw A0708/B0708/C0708 export sheets)**: 確度A here is defined to include **past months too** — a past month tagged 確度A is being used as a stand-in for "realized/actual" (since by the time you're looking back, a past high-confidence month essentially did happen), not double-counted against the separate 承認(実績)/計上 column by design. **This file needs NO 1〜6月 filtering — leave as-is, full year.**
- **`GBC 貢献見込_LATEST.xlsx` / `GBC 貢献実績+見込_COMBINED.xlsx` (what Tableau actually reads)**: 確度A here is defined as **future-only (7月以降)** — i.e. these files DO need past-month (1〜6月, already-elapsed as of the 2026-07-08 snapshot date) forecast rows **removed** before Tableau treats them as "見込". Final rolled-back total (7月以降 only, X confidence dropped per user's explicit instruction): confidence A=456,902,961 / B=217,403,137 / C=735,109,413 (239 data rows). Do NOT confuse this with the pipeline file's ~1,336,386,698 "全期間" A total — they are deliberately different scopes, not a bug in either file.
- Earlier in the same session, before this clarification, ~78 of 79 貢献実績(booked) 案件ID were found to also appear in the (at-the-time-unfiltered, full-year) 貢献見込 confidence-A/B/C data with near-identical amounts (e.g. TCCC ¥140M in both, Agoda ¥120M in both) — this was mistakenly diagnosed as systemic double-counting before the "past-A-stands-in-for-実績" convention was explained. If this pattern is rediscovered later, check which file/convention is in play before re-raising it as a bug.
