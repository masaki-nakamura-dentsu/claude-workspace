## 背景
`8. CAS実績_見込比較 V1.0.twb`の「2026案件ランキング」で案件名がNULL表示になる不具合と、Tableau(このtwb)とPower BIで「前年実績ランキング」「2026年見込ランキング」の数字が違う、という2つの指摘を2026-09-09に調査。[[powerbi_gbc_dashboard_current_state]]・[[qbr_powerbi_tableau_verification_20260906]]の続き。

## 問題1: NULL案件名バグ（修正済み）
`8. CAS実績_見込比較 V1.0.twb`の「2026案件ランキング(1〜7実績+8月以降見込)_」ワークシートは、行ラベルを`GBC CAS実績+見込_COMBINED.xlsx`自身の`件名`/`クライアント名（調整後）`ではなく、別ファイル`Client Name_CAS_SF_FY22 TO DATE.xlsx`の`List`/`List - Project`シートとのリレーションシップ経由で取得していた(旧・数式ベースパイプライン時代の残骸、[[qbr_0708_rollback_tableau]]の"List - Project"に記載の用途と同じ)。
- 件名の一致率93.9%(2,090件中127件不一致、不一致は軒並み7〜8月の新規案件)
- クライアント名の一致率57.9%(さらに悪い。**結合先の列選択ミス**——Actual+側の調整済み名を、List側の生の「クライアント名※最大5,000件」列と比較していた。Listシート自身の「クライアント名（調整後）」列と比較すべきだった)

**修正内容**(2026-09-09、Tableauを閉じた状態を確認の上でtwb XMLを直接編集、バックアップは同フォルダに`..._20260909_backup.twb`):
- 行シェルフの参照を`月別見込親案件: 案件名/Item title（調整後）`(List-Project由来)→`件名`(Actual+直接)、`クライアント名（調整後） (List)`(List由来)→`Calculation_649081307333648396`(=`MIN([クライアント名（調整後）])`、Actual+直接、「2025案件ランキング」ワークシートで既に使われていた計算式を再利用)に差し替え。
- `<datasource-dependencies>`に不足していた`[クライアント名（調整後）]`列と代表クライアント名計算式の定義・column-instanceを追加。
- `<shelf-sorts>`の並び替え対象フィールドも同様に変更。
- XML整形式チェック済み(`xml.etree.ElementTree`でパース成功)。**Tableau側で開いて表示が正しくなっているか目視確認は未実施**(次回Tableauを開いたときに確認要)。

## 問題2: COMBINED.xlsxのActualシート自体がRaw YTDと数値的に食い違っている(未修正・要判断)
NULLバグとは別に、**`GBC CAS実績+見込_COMBINED.xlsx`のActualシート(Tableauの実績データソース)が、Power BI/Raw YTDが示す「真の」CAS実績と2025年で約2,170万円ずれている**ことが判明。

### 検証手順
1. ユーザーがPower BIの「前年案件ランキング」ビジュアルをエクスポートした`data.xlsx`(`~/Downloads/`、161行、Total行=**431,107,609円**)を受領。
2. `GBC CAS実績_FY22 TO DATE.xlsx`(masaki自身のOneDriveミラー、Raw YTDシート)の2025年合計=**435,524,798円**——Power BIの431.1Mに近い(差424万円、部署除外や更新タイミングの違いと推測、未深追い)。
3. `GBC CAS実績+見込_COMBINED.xlsx`のActualシート2025年合計=**457,230,422円**——上記2つより**約2,170万円多い**。
4. 部署別(計上組織名（調整後）)にRaw YTDと突合した結果、**AP1・AP3・BD・SP2・SKの5部署は完全一致**。ズレは**AP2(+18,783,009円)とSP1(+2,922,614円)の2部署だけ**に集中。
5. 月別に見ると明確なパターンが2つ：
   - **AP2の1〜6月**: 毎月ぴったり**+250,000円**のズレ(RawYTDより一律250,000円多い)——特定の1明細行(月額25万円の何かの経費/フィーが重複計上されている可能性)が疑われる。中村さんに確認要。
   - **AP2の7〜12月・SP1の7〜12月**: ズレが月ごとに拡大(AP2は7月+122万円→12月+753万円、SP1は7月+65万円→12月+177万円)。SP1の1〜6月は完全一致(diff=0)なので、SP1のズレは下期のみの現象。COMBINED.xlsx側のActualシートが下期分について、Raw YTDより多い/古いスナップショットの重複データを含んでいる可能性が高い(ただし完全一致の行同士の重複は検出できず——`件名`+`クライアント名`+`DATEVALUE`+`金額`の完全一致キーでの重複チェックは0件だったので、単純な行コピペ重複ではない。クライアント名表記ゆれ(例:「資生堂」vs「(株)資生堂 (ホールディングス作業)」)も絡んでいて、原因の完全特定には至っていない)。

### 結論・次のアクション(ユーザー判断待ち)
- COMBINED.xlsxのActualシートは**単なる「鮮度」の問題ではなく、過去(2025年)のデータ自体に約2,170万円分の水増しがある**可能性が高い。[[qbr_powerbi_tableau_verification_20260906]]で貢献版COMBINED.xlsxが同種の問題(部署フィルタ誤り・列取り違え)を2026-09-06に修正した前例と類似のパターン。
- ユーザーから「Tableauが参照しているCOMBINED.xlsxを最新にデータ更新して」と依頼されたが、**この既存のズレを理解せずに単純追記/更新すると同じ誤りを引きずる**ため、実行前にユーザーに選択肢を提示：(a)現状のActualシートに新規分だけ追記する簡易更新、(b)Raw YTDを正として2025年分を含めてActualシート全体を再構築する抜本修正。後者は貢献版で前例があるが、過去実績の数値が変わるため他の資料(業務指示書等)との整合性に注意が必要。
- AP2の「毎月+25万円」の正体はまだ特定できていない——次回このファイルを触るときの最優先調査項目。
