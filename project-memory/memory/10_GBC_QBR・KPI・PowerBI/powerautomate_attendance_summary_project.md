## 実装済みロジック(「戦略企画部_勤務状況Teams投稿」フローに追加)

既存の個別スレッド返信アクションの後に追加:

1. 変数を最上位で初期化(`日付キー`, `氏名`, `時刻`, `種別`, `勤務形態`, `コメント`, `まとめ本文`, `表示用日付`) ※Power Automateは`変数を初期化する`をトップレベルでしか使えず、条件やループの中では`変数の設定`(SetVariable)しか使えない制約に複数回引っかかった。
2. SharePoint「複数の項目の取得」で本人の当日行を検索→0件なら新規作成、1件以上なら更新。更新は「種別が始業か」で分岐し、該当する時刻・形態の列だけをPatch(もう片方の列は入力欄を空欄のままにして触れない=既存値を保持)。
3. 種別が「終業」のときだけ、当日の全行を再取得し、`and(greater(length(全件),0), equals(length(全件), length(filter(終業時刻が空でない行))))`で「始業した人が全員終業したか」を判定。
4. 真なら、サマリー投稿ログにその日の日付が無いか確認(二重投稿防止)。
5. 無ければ、`join(select(全件, concat(氏名,'　開始(',形態,') ',時刻,' 〜 終了(',形態,') ',時刻)), '<br>')`という**単一の数式**でまとめ文を作成(Apply to each+自己参照のSet Variableで積み上げる方式は「Self reference is not supported」エラーになるため不採用。同時実行度を1にしても解消しなかった)。
6. まとめを、元のカードと**同じ`parentMessageId`**を使って同じスレッドに返信投稿(新規メッセージではなく)。
7. サマリー投稿ログに当日の日付を1行追加して完了。

## ハマった細かい罠(今後のPower Automate作業全般の注意点)

- アクション名を変更しても、**手打ちで式(fx)に直接タイプした`outputs('アクション名')`という文字列参照は自動追従しない**(UIの動的なコンテンツから挿入したものだけ自動追従する)。今回、「複数の項目の取得」(本人の当日行取得)を改名した際、それを参照する箇所が3箇所(条件自身の判定式+項目の更新×2)もあり、1箇所ずつ気づかず何度もエラーになった。最終的にこのアクションだけは改名を諦め、元の名前「複数の項目の取得」に戻して解決。
- 日本語IMEでの手打ち編集は全角/半角スペースの混入リスクがあり、コピー&ペーストで一致させる方が安全。
- 二重押し(同じボタンを連打)は基本的に同じ列を上書きするだけで安全だが、ごく短時間(1秒未満)での連打は「複数の項目の取得」がまだ反映されていない状態で新規作成に走り、同日同名で行が2つできるリスクがある。その場合、片方の行の終業時刻が永遠に空のままになり「全員終業判定」が成立しなくなる。ユーザーは把握の上、まずはこのまま様子見と判断(実際に重複が起きたら「氏名の重複を除いた人数」ベースの判定に直す想定)。

## 実運用テストで発覚した追加バグ(2026-08-06〜08-12)とその修正

実際に複数人で始業/終業を押してもらうテストを重ねた結果、「全員終業したのにまとめが投稿されない」という不具合が発生。原因は2段階あった。

1. **書き込み直後の読み直しタイムラグ**(2026-08-06、当初の誤診断): 「本日の全件取得」の直前に5秒の「遅延」アクションを追加して対処 → これは効果があったが根本原因ではなかった。
2. **本当の原因**(2026-08-12、正しく特定): SharePointの列は表示名(`終業時刻`等)と内部名(`OData__x5c31__x696d__x6642__x523b_`等、[[power_automate_gotchas]]のルール6参照)が異なる。`$filter`クエリだけでなく、`item()?['終業時刻']`のような**式内のプロパティアクセスも内部名が必要**だったが、Apply to each内の完了判定条件と、まとめ本文組み立ての`select()`式の両方で表示名のまま参照していたため、`empty(item()?['終業時刻'])`が常にtrue(＝常に「未終業」)と誤判定され続けていた。エラーは一切出ないタイプの不具合だったため発見に時間がかかった。

修正: 両箇所を内部名(`OData__x6c0f__x540d_`=氏名, `OData__x59cb__x696d__x5f62__x614b_`=始業形態, `OData__x958b__x59cb__x6642__x523b_`=始業時刻, `OData__x5c31__x696d__x5f62__x614b_`=終業形態, `OData__x5c31__x696d__x6642__x523b_`=終業時刻)に置き換え。

**さらに詰まった点**: 「まとめ本文組み立て」側の修正はPower Automateデザイナー上での通常の編集(チップをクリック→式タブ→編集→更新→保存)で問題なく反映されたが、「Apply to eachの中の条件」側だけは**同じ手順を4回以上試しても保存後に元の値に戻ってしまう**という再現性のある問題が発生(詳細は[[power_automate_gotchas]]ルール7)。最終的にはUIでの再試行を諦め、**エクスポートしたパッケージのdefinition.jsonを直接テキスト置換で修正し、「パッケージのインポート(レガシ)」から既存フローへの「更新」としてインポートし直す**方法で解決。この方法はユーザー本人がブラウザで手動アップロード・インポートボタンを押す形で完了させた(Claude側のブラウザ自動操作はトークン消費が大きいと指摘があり、最後のインポート実行はユーザーに引き継いだ)。

修正後、エクスポートしたJSONを直接確認し、両方の式が正しい内部名になっていることを確定的に検証済み(2026-08-13)。
