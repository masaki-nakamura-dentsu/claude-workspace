## 背景・経緯
[[qbr_cas_combined_vs_rawytd_ap2sp1_gap_20260909]]の続き。前日(9/9)にTableauの`8. CAS実績_見込比較 V1.0.twb`側のNULLバグ・重複計上バグを修正した後、9/10にPower BI側の「案件別ランキング(実績+見込ブレンド)」チャート(`案件別ブレンド値`メジュー)でも同種の実績過少表示が発覚し、調査を継続した。

## 調査の流れ(すべて確認済み事実)
1. **月境目切替(1月固定)の疑い→否定**: 正樹さんが確認、月スライサーは8月になっていたが症状継続。
2. **`案件_Dim`のTREATAS結合、物理リレーションシップ無し(既知のプラットフォームバグ回避策)の疑い**: DAXクエリで`案件_Dim`とRaw YTD双方のID文字列・文字数を突き合わせ→完全一致(15桁、双方とも`a1hGA00000A0Q1Q`)と確認、この時点では「IDは合っている」と誤認。
3. **`FILTER(ALL('Raw YTD'[月番号]), ...)`のDAX計算列バグ([[powerbi_gbc_dashboard_current_state]]§6-2の既知バグクラスそのもの)**: `Raw YTD[月番号]=MONTH([計上月])`がDAX計算列であることをpbixrayで確認、`ALL(単一計算列)`が正しく機能しない既知バグと判明。`ALL('Raw YTD')`(テーブル全体)に変更する応急処置(A)で改善したかに見えた。
4. **(A)の副作用発覚**: `ALL('Raw YTD')`はテーブル全体のフィルタを消すため、本来効いていた「計上年」の絞り込みも消え、**前年(2025年)の同じ月範囲の実績まで合算**されてしまう例(Shiseido Media AOR 2025が2026年ランキングに37.3Mとして混入)が発覚。`VAR SelectedYear = ...`を追加し、`FILTER(ALL(テーブル[年度/計上年]), 列=SelectedYear)`を明示的に加える修正で解決(確認済み)。
5. **ここで別の症状発覚**: BATとヤクルトインバウンド競合が**全く同じ金額**になる、クライアント名が空欄になる、という新しい症状。当初「表示キャッシュの不具合」と誤診断(リフレッシュを提案したが改善せず)。
6. **真因特定**: `Prep_SalesforceAllRecord.xlsx`(`SF案件リスト_旧Excel`の元ファイル)を全件チェックした結果、**大文字小文字だけが違う案件IDの衝突ペアが110組**存在することを発見(BAT/ヤクルト、アンメルツ/サイボウズもその一部)。DAXの`=`/`TREATAS`は大文字小文字を区別しないため、この衝突ペアが同一IDとして扱われ、片方の実績がもう片方に混入 or 消失していた。
7. **応急対応(A): `TREATAS`→`EXACT()`ベースの`FILTER`に置き換え**(大文字小文字を区別する結合に変更)を試したが、**BATが完全に消失**する新しい症状が発生。診断用DAXクエリ(`案件_Dim`のBAT行のIDと、Raw YTD各行のID・EXACT一致列を並べて出力)を正樹さんに実行してもらった結果、**`案件_Dim`で「British American Tobacco Japan, Ltd.」という案件名自体が、本来ヤクルト側のはずの大文字Q版ID(`a1hGA00000A0Q1Q`)に紐付いている**ことが判明(手元のExcelファイル直接確認では逆=BATが小文字q版だったが、ライブモデルの`案件_Dim`では逆転していた)。**つまり衝突は`案件別ブレンド値`メジューの結合ロジックだけでなく、`案件_Dim`というディメンションテーブル自体の構築(Table.Distinctによる重複排除)の時点で既に発生している**。EXACT()でメジュー側だけ直しても、`案件_Dim`が最初から間違ったID紐付けを持っていれば直らない。
   - **注記**: この診断クエリ自体、Raw YTD側の`[案件名]`絞り込みを付け忘れたため全318件近く返ってきてしまった(私のクエリ設計ミス、[[feedback_give_full_code_not_partial_diffs]]の「渡す前にセルフチェック」教訓が別の形で再発)。ただし結果の中の`案件_DimのID`列が終始`a1hGA00000A0Q1Q`(大文字Q)だった事実自体は確認できており、上記の結論は揺るがない。

## 根本原因(確定)
`SF案件リスト`(Salesforce直結の新クエリ)のPower Query M式末尾:
```
案件ID正規化 = Table.TransformColumns(..., {{"案件 ID/Item ID", each if _ <> null then Text.Start(_, 15) else _, type text}})
```
Salesforceの正式な18桁IDをわざわざ15桁に切り詰めている。18桁IDの末尾3文字は15桁部分の大文字小文字パターンを表すチェックサムなので、15桁への切り詰めはこのチェックサムを捨てて衝突リスクを呼び込む設計になっている。[[kgikpi_cas_uriage_soritsuki_rename.md]]とは無関係の、2026-08-25(18桁/15桁不一致解消時)に遡る既存の設計判断が原因。[[powerbi_gbc_dashboard_current_state]]の「案件IDの桁数」節に記載された15桁正規化の決定そのものが、今回の110組衝突の温床になっていた。

## なぜ今まで顕在化しなかったか(正樹さんへの回答として整理済み)
衝突自体は15桁化された時点(2026-08-25)からデータに存在していたが、**部署別・年別等の集計レベルのメジューでは、衝突した2案件が同じ合計に埋もれるため合計値がズレて見えない**。「案件別ランキング」は数あるメジューの中で唯一「1案件だけを`案件_Dim`+`TREATAS`で切り出す」設計だったため、初めて可視化された。他の44個のメジューは影響を受けていないと考えられる(未検証、要注意)。

## なぜTableauでは同じ問題が出ないか
ツールの優劣ではなく実装の違い。Tableau側の同名チャートはRaw YTD/COMBINED.xlsx自身の`件名`テキスト列で直接グループ化しており、ID経由の結合(`案件_Dim`のような別テーブルとのTREATAS結合)を一切使っていない。Power BI側でも「CAS売総 実績 案件別内訳」ページは同じ理由(Raw YTD自身のテキスト列を直接見ている)で最初から無傷だった。

**次の分岐点**: 本格対応(18桁化、4箇所)に進むか、方針をユーザーと確認する必要がある(応急パッチでは`案件_Dim`自体の構築段階の汚染は直せないことも再確認済み)。

## 【別バグ発見・修正完了】`案件別ブレンド値`メジューのBLANK誤爆(2026-09-10)
順位ズレ調査中、TableauエクスポートとPower BIエクスポートを突合したところ、Power BI側に**多数の無関係な案件が全く同一の値`-1,963,108`を示す**異常を発見(25件以上)。

**原因**: `案件別ブレンド値`メジュー(pbixray調査で確認)が`SELECTEDVALUE('案件_Dim'[案件 ID/Item ID])`で単一IDを取得し`EXACT('Raw YTD'[案件 ID/Item ID], SelectedDealID)`で絞り込む設計だったが、**Salesforce側に同一案件名で複数ID(例: "Nanoeブランディング"が3件)が存在するケースでSELECTEDVALUEがBLANKを返し**、`EXACT(x, BLANK())`が「Crosstable未紐付けの実績行838件・合計205,888,440円」を丸ごと誤って拾ってしまっていた。診断は`SELECTEDVALUE`を`案件名`で絞り込むDAXクエリでTargetID=BLANKを確認、`案件_Dim`側で該当案件名が複数IDに分裂していることも確認。左パネルの`前年実績値`メジューは`TREATAS(VALUES(...))`ベースで複数IDでも正しく合算されるため無傷だった(左右パネルで同じ案件名でも挙動が違う理由の説明にもなる)。
**今回の18桁化とは無関係の既存バグ**(前回セッションで「EXACT()版は不十分と判断・見送った」はずが、実際にはそのままメジューに残っていた)。
**修正**: `案件別ブレンド値`メジューの`RETURN`直後に`IF(ISBLANK(SelectedDealID), BLANK(), ...)`のガードを追加(他のロジックは無変更)。反映・データ更新後、`-1,963,108`の異常行は**0件に解消**、テーブル総行数も317→140行に減少(実在しない重複名の"幽霊行"も解消)。**確定・解決済み。**

**クライアント名空欄の残り**: 2026年側(全41件→実質2件)に加え、**前年(2025年)案件ランキング側でも別途19件のクライアント名空欄を発見・Salesforceリンク生成済み**(2026-09-10、正樹さんが順次修正中)。`プロダクト：訪日中国人メディア開発（２０２６年）`は対応不要と確認済み。`NARUTO25周年競合`は提示済みのSalesforceリンクでの修正がまだ反映されていない可能性、要確認。2025年側19件のID・部署名一覧は本セッションのチャット履歴参照(未保存、次回必要なら再度`案件_Dim`をクライアント名空欄でFILTERして取得可能)。
