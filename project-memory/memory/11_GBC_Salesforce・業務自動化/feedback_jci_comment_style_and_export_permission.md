- **戦略企画部コメントは必ず先頭に最初にコメントした日付を `10/22 ` の形式で入れる。** 追記時は前のコメントを残し改行して新しい日付で足す。
- **「〜の記入が必要です」「入力してください」のような不足指摘は書かない(見る側がネガティブに受け取る)。その項目をどう対応したか(例: 「獲得グループは不明/Unknownを補完しました」「選択肢Xに変更しました」)を書く。** 例: 10/22の自分の書き方(「〜に変更しました」)が正。9/28分の「入れて下さい」系は旧表現で、今後は使わない。
**Why:** ユーザー指示(2026-10-22)。BD部・拠点が読むコメントなので、依頼調ではなく結果報告の形にする。
**How to apply:** build_import_csv.pyの要確認レポート(内部向け)は対象外。Excel(AP列)/SFに入るコメントのみ。

- **Salesforceレポートのエクスポートは今後Claudeが実行してよい(2026-10-22許可)。** 本人承認(Authenticatorのプッシュ等)が出たら、ユーザーが端末で承認する。手順は [[salesforce_report_download_automation]]。エクスポートが面倒なときは、遅延描画グリッドをスクロール収集する方法でも代用可(462行取得できた)。
- 取込後の確認: レポートのxlsxエクスポートとCSVを突合(複数選択の並び順差は無視、日付は0埋め無視)、月別見込は親のGroup売総(JPY)>0・外貨合計一致で確認。

## 追記(2026-10-22 再指示)
- 書き方は「どの項目を、こういう判断で、こう入力した」(例:「獲得グループ: 「Not announced」は選択肢にないため、意味が近い「非開示/Not Disclosed」を選択しました。」)。「補完します」等の一方的・予告調も避け、完了形で書く。今後も継続。
- **SFのコメント項目は約255字上限**: 291字でSTRING_TOO_LONG失敗(Vistra)、246字はOK。250字以内に収める。
- 修正手順: Excel XML直接編集→別名_NN保存→build_import_csv.pyで再生成→変更行だけID付き更新CSVにして parent-update で再取込(新規登録済み行はID払い出し一覧でID付与)。

- 過去に日付なしで入っていたコメントは、BD部Excelの初出版から推定日を付け「4/28時点 …」の形で補完(2026-10-22実施、23件)。新規コメントは必ず日付先頭。
