## 場所とファイル構成
`Work/GBC_戦略企画部/GBC経営企画グローバル戦略分析／競合分析など/今後の業況見通し/` 配下。
- `今後の業況見通し_更新マニュアル.rtf` — 手順書（RTF形式、`textutil -convert txt -stdout` で読める）
- 月別フォルダ（例 `202607`）に、Salesforceからエクスポートした業務リスト `GBC (30)-YYYY-MM-DD-...xlsx`（過去30日の活動報告、フェーズは「仕掛中/未受注」のみでフィルタ済み）と、提出済みなら `【YYYY年M月分】■下書き用ファイル_重要情報アンケート_記入済み.xlsx` が入る
- 空テンプレは `■下書き用ファイル_重要情報アンケート.xlsx`（シート名「下書き用シート」、C15=業況見通し選択欄、D13:E17マージセルが理由欄）

## 判断ロジック（②理由欄の勝利/敗退/仕掛の抽出）
Salesforceの業務リストはPhase=「仕掛中/未受注」でフィルタされているため、勝敗はPhaseでは判別できない。**案件概要/アップデート(5W1H)欄の自由記述テキストから当該月の決定・開始を読み取る**しかない。
- 全行に対し「勝利/敗退/受注/失注/決定/仕掛/開始/獲得」等のキーワードでスクリーニングし、ヒットした案件のdetail/report全文を読んで個別判断
- 前月・前々月以前の確定分と重複しないよう、**過去の記入済みファイルをgrepしてクライアント名/案件名が既出でないか必ず確認**（例: 2026年7月分ではCFA InstituteとAutodeskの「仕掛」がそれぞれ3月・4月分に既出だったため、7月は「勝利」としてのみ計上）
- 前月/今月の業務リストのタイトル差分（disappeared/newly appeared）は、サブタイトル変更や30日ウィンドウ非該当による見かけ上の増減が大量に混ざりノイズが大きいため、主判断には使わない。あくまで当月リスト内の自由記述の日付言及（例「7/21更新」「■26/7/28」）で当月確定かどうかを判定する
- 規模の小さい既存クライアント内の通常業務（ルーティン更新、単発の受注済み制作進行など)は対象外。「ある程度の規模がある主なピッチ競合案件」に限定
- 「見送り」（クライアント都合で当年度実施中止）は敗退に準じて計上してよい（2026年7月分でカーライル・ジャパンPitchが該当）

## 記入フォーマット（2026年7月分でユーザーが最終確定・修正した仕様。これを毎回のデフォルトとする）
D13セルに以下の構造でまとめて記入。**見出し（■【】行）の間だけ改行し、各見出し内の案件は改行ではなく「、」区切りで1行にまとめる**（6月分は案件ごと改行だったが、7月分でユーザーが「、」区切りに手直しした。これが最新の正）：
```
■【勝利 (X月内決定分のみ)】
クライアント／案件名（エリア・種別）、クライアント／案件名（エリア・種別）、...
■【敗退 (X月内決定分のみ)】
...（同様に「、」区切り）
■【仕掛 (X月からの開始案件のみ)】
...（同様に「、」区切り）
■【コメント】
不安定な国際情勢（米国・ロシア・中東・台湾）が国際マーケティングに与える影響を注視。
```
D13のフォントサイズは10pt。
C12直下の業況見通し選択肢は、テンプレ上C13〜C17に「良くなる/やや良くなる/どちらともいえない/やや悪くなる/悪くなる」の5択が並んでいるが、**選ばない4つ（C13,C14,C16,C17）のテキストは削除し、選択する「どちらともいえない」（C15）だけを残す**（空テンプレのままだと余計な選択肢文言が残ってしまうため、ユーザーが7月分で削除。次回からは最初からこの形で作る）。
行11〜17の行の高さはユーザーが48.0に調整済み（テンプレ由来のデフォルトより広い）。次回作成時も踏襲してよい。
セクションA（重要案件の受注・取引先動向）は過去の全記入済みファイルで一貫して未記入（プレースホルダーの〇〇社/△△社/□□社のまま）。マニュアル・ユーザー指示ともにA欄への言及がないため、B欄（①②）のみ記入するのが正しい運用。

## ファイル命名
最新の慣行は `【YYYY年M月分】■下書き用ファイル_重要情報アンケート_記入済み.xlsx`。openpyxlで空テンプレを読み込み、C13/C14/C16/C17を削除・C15とD13を記入・行高さ48/フォント10ptに調整して別名保存すればよい（フォーマット内に数式は無いので[[openpyxl_empty_v_tag_corruption]]の心配は不要と確認済み）。

## 次回（8月分以降）の自動実行手順
ユーザーは「毎月同じことをするので、次回から細かい指示なしで自分で用意しておいて」と明言（2026-08-03）。次回以降、「○月分の業況見通しを作って」とだけ指示されたら、以下を自分で実行してよい（都度の細かい確認は不要、この手順書どおりに進める）：
1. `今後の業況見通し/` 配下の対象月フォルダ（無ければ作成）にあるSalesforce業務リスト`GBC (30)-...xlsx`（当月分・前月分）を読み込む
2. 過去の全月の記入済みファイル（`【YYYY年M月分】...記入済み.xlsx`）を全部grepし、既出のクライアント名・案件名を洗い出す（重複計上防止のため必須）
3. 当月リストの自由記述（detail/report/nextstep）を勝利/敗退/受注/失注/決定/仕掛/開始/獲得等のキーワードでスクリーニングし、該当行を全文読んで「規模のある主要ピッチ競合案件」で「当月に決定・開始」したものだけを判断・抽出（既出案件は除外）
4. 上記フォーマット（■見出し+「、」区切り、C15固定、選択肢4つ削除、行高48/フォント10pt）で新規ファイルを作成・保存
5. 保存後、必ず内容をユーザーに提示して最終確認を仰ぐ（判断が入る作業のため、ファイル作成自体は自動でよいが、送信前のレビューは引き続き必要）

勝利: 花王ベトナムBioréローンチキャンペーン競合ピッチ（予算約3,400万円）、台湾観光局観光誘致プロモーション施策2026-2027（5月分「仕掛」が本月確定）
敗退: ANA Global Creative Pitch（6月分「仕掛」が本月確定、BBDOに敗北）、トリドリシャンプー台湾ロンチ（クライアント都合により本年度実施見送り）
仕掛: Toyota(TMA) Gazoo Racing リージョナルエージェンシー選定ピッチ（Havas/T&P/Virtueとの4社競合、予算S$700K、9/4プレゼン予定）

**Salesforceダウンロードで手順が変わった**: 専用スクリプト(`download_step1_export.py`, port 9224)が[[sf_reports_qbr_download_automation]]の共有ボットブラウザ(port 9226、同じprofile dirを使用)と競合して失敗した。詳細と回避策は[[salesforce_report_download_automation]]の2026-08-31更新箇所を参照。次回はまず`lsof -i :9226`で共有ブラウザの起動有無を確認し、動いていれば最初からreports_pipelineの`download_one_report`を再利用する方式で進めること。

**スクリーニング後の除外理由をユーザーに聞かれた実例（8月分）**: キーワードヒットしたが計上しなかった案件について「未確定（トライアル/検討/意向表明段階）」「既出案件と重複」「規模小さい/ルーティン業務」「社内ツール開発（ピッチではない）」の4分類で一覧提示すると納得を得られた。次回以降、確認を仰ぐ際にこの分類パターンを再利用してよい。

## 2026年9月分の実例（勝利6件/敗退3件/仕掛4件）2026-10-01作成
勝利: Toyota(TMA) Gazoo Racing リージョナルエージェンシー選定ピッチ（8月分「仕掛」が本月勝利確定）、Toyota Kazakhstanメディアエージェンシーピッチ（7月分「仕掛」が本月勝利確定）、TrendLifeグローバルピッチ支援、ANA Global Digital Media Pitch（7月分「仕掛」が本月勝利確定）、TikTok LIVE FEST Pitch（6月分「仕掛」が本月勝利確定）、WOSADO（中国メーカー）日本ローンチキャンペーン（予算約2億・競合明記なしだがユーザー判断で勝利に算入）
敗退: 富士通グローバルブランディングピッチ（5月分「仕掛」が本月敗退確定）、久光製薬USサロンパスメディアピッチ、インスパイアリゾート リージョンメディアピッチ（ユーザー指示で追加・電通側が準備期間不足等によりRFP辞退＝「敗退」ではなく「辞退」としてニュアンス付記の上で敗退欄に計上）

**新しい判断パターン（9月分でユーザーが追加確定）**:
1. **競合言及のない受注確定案件も、規模が大きければユーザー判断で「勝利」に算入してよい**（WOSADOの例：競合プロセスの記載が本文になくても、予算規模(2億)があれば一次スクリーニングでは除外候補として提示しつつ、ユーザーが「勝利に入れて」と言えばそのまま追加する）。自動実行時は機械的に除外せず、除外候補として提示だけはすること。
2. **自社都合でのピッチ辞退（RFP受領後に準備期間不足・体制不備等で参加を見送るケース）は「敗退」とは性質が異なるが、ユーザーの指示でその旨を括弧書きで注記した上で敗退欄に計上してよい**（例: `インスパイアリゾート リージョンメディアピッチ（日中韓・メディア；準備期間不足等により電通側辞退）`）。これは既存の「見送り」（クライアント都合）パターンの応用形。次回以降、同様の自社都合辞退案件があれば、まず除外候補として提示し、ユーザーに「辞退として敗退欄に入れるか」を確認するとよい。

## Salesforceダウンロードのリトライ挙動（2026-09-30以降の運用で確認）
`download_one_report_with_retry`は1回目`ERR_ABORTED`、2回目「レポートビルダーのiframeが見つかりません」で失敗しても3回目（RETRY_COUNT=3、20秒間隔）で自動的に成功することがある。1〜2回目の失敗ログが出ても慌てず3回目の結果を待てばよい。
