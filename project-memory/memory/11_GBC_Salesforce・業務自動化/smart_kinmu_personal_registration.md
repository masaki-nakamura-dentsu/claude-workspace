中村さん本人の勤務登録(https://smtkin.dentsu.co.jp/laborsmart/smart)を代行する仕組み。部署分析の [[gbc_smart_kinmu_automation]] とは別物。

## ユーザー指定ルール(2026-10-13)
- 就業開始/終了 = 常にSharePointリスト「SK部_出退勤記録」(esq365 /sites/SKB/Lists/SK_)の始業/終業時刻。**出社日でも入館時刻は開始に使わない**(2026-10-13訂正: 10/8を入館09:15で登録→ユーザーがSP始業09:20に手修正。「出社からの勤務開始」=SPの始業時刻のこと)。入退館時刻は昼休みの位置決めにだけ使う。
- 混在パターンは2通りある(2026-10-13ユーザー明示): (a) 在宅→出社(始業形態=在宅、終業形態=出社): 入館時刻の直前1時間を昼休みに(例 10/7 入館12:57→12:00-13:00、9/15 入館13:18→12:30-13:30)。(b) 出社→在宅(始業形態=出社、終業形態=在宅、朝から会社で途中で在宅へ切替): 退館時刻から1時間を昼休みに(例 10/5 退館11:14→11:15-12:15、9/16 退館13:01→13:00-14:00)。どちらも勤務場所は「在宅」「出社」両方を選択。
- 昼休み1時間。在宅⇔出社が混在する日は移動時間を昼休みに充てる(入館/退館時刻に合わせる。例 入館12:57→12:00-13:00、退館11:14→11:15-12:15、入館13:18→12:30-13:30)。それ以外は12:00-13:00。
- 作業詳細はOutlook予定(~/CalendarExport/calendar_events.json、時刻はUTC→+9h)、メール、Claudeセッションログ、work_statusから推定。新規項目は作らず「履歴」の既存組み合わせ(JU/作業領域/作業詳細)を使う。
- 予定表の扱い(2026-10-14ユーザー指定): 仮(tentative)の予定と予定あり(busy)が重なる時間帯は、予定ありの内容を優先する。仮の予定は参加していないことがある(10/13のBD部部会=仮→不参加、ユーザーが自分で修正)ので、仮の予定だけを根拠にブロックを立てるときは控えめに扱う。
- 当日(未終業)は登録しない。休暇日(年次休暇の仮登録等)は触らない。

## 技術メモ
- 共有ボットブラウザ9226(Chromeの保存パスワードでID/PW自動入力済み→Loginクリックで入れる)。
- スクリプト: `~/SmartKinmuReg/full.js <day.json>`(日パネル入力→作業実績へ→ブロック分割→履歴から内容一致で選択)。その後 `#DECISION`(=登録)をクリック→確認モーダル `#pov_ok`。`verify.js`で各ブロックの内容確認。
- 2026-10-14追加: `sp.js`=SPリストから10月の始業/終業取得(9226のesq365-myタブをSKBへ遷移してq2.txt実行)。`login.js`=Loginクリック+日パネル表示(入退館時刻はここで読む)。`hdump.js`=履歴の全組み合わせ一覧(保存しない)。`submit.js`は#DECISIONに修正済み。手順: sp.js→login.js→hdump.js→dXXXX.json作成→full.js→submit.js→hist.jsで確認→chk.jsでステータス確認→closetabs.jsで使ったタブを閉じる。
- 昼休み位置の丸め: 入館時刻を15分単位で切り上げた時刻を終わりに1時間(10:51→10:00-11:00)。開始ブロックは始業を15分単位で切り下げ(08:11→08:00)。
- 勤務場所は `div.jiko_jizen[variable=zaitaku|shussha]` のトグル。ブロック追加は `openJuDialog('YYYY-MM-DDTHH:mm_YYYY-MM-DDTHH:mm','MODE_GRID')`、履歴は `#ju_history`→`hListSelect(n)`。
- 落とし穴: 履歴の番号は使用順で毎回並び替わる→必ずテキスト一致で選ぶ。履歴セルの空白はNBSP(要正規化)。登録ボタンは<button>ではなく `input#DECISION`。作業実績画面で保存前にページ遷移すると入力が消える。

- 2026-10-15追加: 履歴にあっても**非公開化された組み合わせ**がある(例「チームビルディング/DJ-その他/GBC内企画」)。登録時にEY-350「HH:MM-HH:MMのセルが非公開状態です」が出て保存されず、submit.jsは無言で終わる→必ず`chk.js`(日パネルのステータス=承認待ちか)で確認。エラー時は`sub6.js`(登録→OK→スクショc2.png)で原因を見る。社員食堂グローバルメニュー企画(ポスター・メニュー表・料理イラスト等)は**Global Qの作業**として登録する(2026-10-15ユーザー訂正。10/14分はユーザーが自分で修正済み)。
- 9226が落ちていたら: `--remote-debugging-port=9226 --user-data-dir=~/SalesforceExport/browser_profile --window-position=-2500,-2500`でnohup起動→`open2.js`(SKBとsmtkinタブを開く)→`sso.js`(Okta確認ボタン+MSアカウント選択をクリック、PWは自動入力済み)。login.jsの日付は毎回sedで書き換え。

## ユーザー指定ルール追加(2026-10-28)
- **在宅で始業・終業し、途中に出社が挟まる日**(SPは始業終業とも在宅、入退館時刻が日中にある): 出社の前後それぞれ1時間が移動時間=休憩扱い。休憩1=入館時刻の直前1時間(入館13:00→12:00-13:00)、休憩2(`break_start_time_2/break_end_time_2`)=退館時刻から1時間(退館16:39→16:30-17:30、開始は15分切り下げ)。10/27でユーザーが休憩2を足して実証。勤務場所は在宅+出社の両方。休憩2の時間帯にはブロックを置かない(full3.jsは休憩2未対応→要拡張)。
- **毎回、登録前に前日までの登録に対するユーザー修正を確認する**: smtkinの日パネルで直近登録日の休憩・ブロック・勤務場所を読み、自分が登録した内容(上の実績節・dXXXX.json)との差分を取り、差分から新ルールを学んでこのファイルに追記してから次の日を登録する。ユーザーが最終チェックをしている。
- 10/27の実例: 自分の登録=休憩12:00-13:00のみ → ユーザー修正で休憩16:30-17:30を追加。
