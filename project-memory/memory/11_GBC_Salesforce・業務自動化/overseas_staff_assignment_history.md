[[overseas_staff_list_sync_automation]]で集めた月次スナップショット(2019-09〜2026-09、71件・重複除去済み)から、
氏名別の駐在履歴(国・都市・期間)を再構築した。将来的にAgency OS(agencyスキル、researcher/strategic-planner等)
の「知見」として使う想定とのこと。

## 前提となる重要な制約
各月のファイルは「その時点の在籍名簿」のスナップショットであり、個々人の異動発令日そのものは含まれていない。
そのため開始日/終了日は「その配属が確認できた最初/最後のスナップショット日」の近似値(左右打ち切りあり)。
スナップショットに欠落期間があるため(例: 2024-02〜2024-07、2021-07〜2022-01等)、その間の異動を捉えられていない
可能性がある。出力ファイルの「データソースについて」シートに前提・限界と収集済みスナップショット日一覧を明記済み。

## 成果物
- ツール: `~/OverseasStaffList/build_assignment_history.py`(再実行可能、実行するたびその時点のarchiveフォルダ内容から再生成)
- 出力先(2026-09-03、ユーザー指示により変更): `Global Q - 駐在員リスト/overseas_staff_assignment_history_<YYYYMMDD>.xlsx`
  (共有OneDrive同期フォルダ、[[overseas_staff_list_sync_automation]]の保存先と同じ場所。ローカル専用の`~/OverseasStaffList/`には置かない)
  - シート「駐在履歴」: 342セグメント(283名、うち49名は複数配属=異動あり)。列は氏名/国/都市/赴任先(参考)/確認開始月/確認終了月/現在駐在中/観測回数/備考
  - **日付は年月のみ(YYYY-MM)で表示** — ユーザーから「ファイル名に月情報があるので日までは不要」と指摘され、当初のYYYY-MM-DD表示から変更した。内部的にはdate(year,month,1)に正規化して扱っている。

## 実装上の重要な学び
- **氏名の表記ゆれ対策**: 同一人物でもファイルの年代によって「姓 名」(半角スペース区切り)と「姓名」(区切りなし)の
  両方の表記が混在していた(全角スペース　は事前に正規化していたが、区切りなし表記との揺れは別問題)。
  結合キー自体はスペース除去で正しく統一されていたが、**表示用の氏名がセグメントごとに元ファイルの表記のまま
  だと同一人物が別人に見えてしまうバグがあった** → 各人物キーごとに「最も新しいスナップショットでの表記」を
  正式表示名として全セグメントに適用する形で修正済み。同種の名寄せ処理(複数時点のExcel名簿を統合する系のタスク)
  では今後も同じ罠に注意。
- **都市表記の揺れ**: 2025年9月以降の新形式は都市を"LA"/"NY"のような略称で記載するようになった(それ以前は
  "ロサンゼルス"/"ニューヨーク"のフルネーム)。正規化しないと同一都市が異動したように誤判定されるため、
  `CITY_NORM`辞書(LA→ロサンゼルス、NY→ニューヨーク)で吸収した。他の都市でも将来同様の略称化が起きたら
  同様に辞書へ追加する必要がある。
- ファイル構造は年代によって列構成が3パターンに分かれる(2020-2023頃:「居住国」列に「国／都市」を1セルで結合、
  2024年globalQ掲載用:同様の結合形式、2025年9月以降:「駐在国」と「都市」が別列+メールアドレス列追加)。
  ヘッダー行を"氏名"というセル値の存在で検出し、列名ベースでマッピングする実装のため、将来また列構成が
  変わっても大きな修正なしで対応できる可能性が高い。
