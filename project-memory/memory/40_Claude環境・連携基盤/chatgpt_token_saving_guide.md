**トークン概算ツールの実装メモ**: 単純な文字数×係数の概算では日英で似た数字になってしまう不具合があった。文字種(CJK/ラテン/空白/記号)を判定し、CJKは1〜2文字ごと、ラテンは4文字ごとにチャンク化する自前の簡易トークナイザー(`tokenizeApprox`)に置き換え、チップ表示の区切りと実際のカウントを常に一致させた。本物のBPEトークナイザーとは完全一致しない旨を明記している。

**2026-09-28、簡易トークン比較ツールのバグ発見・修正**: ユーザーから「英語のほうがトークン数が多く出るのはおかしい」と指摘。原因は`tokenizeApprox`の英語(Latin)側チャンク処理: 単語ごとに`pendingSpace+word`を作ってから4文字区切りでMath.ceil丸めしていたため、4〜5文字程度の単語でも空白込みで5文字になり2トークンに水増しされる、という単語境界ごとのリセットによる過大カウントバグだった(継続的なバイト列として4文字区切りにする本来の挙動と乖離)。pip3でtiktokenを導入し実際のcl100k_base/o200k_baseでデフォルト例文(JA「来週の企画会議...」/EN「For next week's planning meeting...」)をエンコードして裏取りしたところ、o200k_baseで日本語47トークン・英語32トークンとなり日本語が明確に多いことを確認(この2文はほぼ内容的に対応するプロンプト)。修正版は「単語(前の空白込み)が10文字以内ならまるごと1トークン、それを超える長い単語だけ2分割」というロジックに変更、実測に近い47対33を再現できた。日本語側のCJKチャンク処理(1〜2文字交互)は変更不要と判断(01節のサンプル文「吾輩は猫である...」もtiktoken実測13トークンに対し概算12トークンと近い)。UIの注記文言「英語はおよそ4文字ごと」も「英語は単語ひとまとまりごと・長い単語のみ分割」に修正。Version 10として再公開。**今後のTips**: このデックのようなライブ概算ツールを作る際は、tiktoken(`pip3 install tiktoken`、d14461でも通った)で実測値を先に取り、ヒューリスティックが実態と乖離していないか検証してから公開するのが安全。
