- 記録先はSalesforce。ユーザーが仮レポートを作成済み：**「AI活用PJ: 過去1ヶ月更新内容」(レポートID `00OfP00000K01LZUAZ`)**。レポートタイプは「GBC案件/Items が関連する活動」＝**`GBC__c`(GBC案件/Items)の子オブジェクトである「活動項目/Activity Items」**を使っており、[[powerbi_migration_gbc_dashboard]]で扱っている売上総利益集計元のGBC__c本体とは別データなので、金額を入れる必要がなく実績集計を汚さない(ユーザー確認済み)。

## 2026-08-18: プッシュ型(Tips配信)とプル型(アンバサダーのヒアリング)を統合
朝、個人Macのセッションで「GBC週刊AI Tips」Vol.1(Week01-08)・Vol.2(Week09-16、応用編)をArtifactとして作成済みだったが、会社Mac側のメモリには同期されておらず(work_statusログにも記録なし)、ユーザーがArtifact URLを直接共有して内容を伝えてくれた。**教訓**: 他Macでの作業がメモリに同期されていない場合、Artifact/ファイルの直接URLを教えてもらえれば[[dropbox_config_sync]]の同期待ちを待たずに内容を復元できる。

Tips集の構成: 各週1テーマ×ChatGPT/Copilot2種の具体的プロンプト付き。Vol.1は戦略企画部中心の一般的シーン(議事録、メール下書き、ピッチリスト分類、市場リサーチ、提案書ストーリーライン、QBR資料、勤務データ整形、多言語会議)。Vol.2は他部署向けの「複合プロンプト」(①②③形式で一度に複数成果物を出す)、部署タグ付き(AP部/SP部/業務管理部/局付け/拠点事業プロデュース部)。共通の注意点に「使い方の相談は各部のAIアンバサダーへ」と既に明記されており、アンバサダー制度と自然に接続する設計。

ユーザーの整理：Tips配信＝**プッシュ型**、アンバサダーのヒアリング＝**プル型**で、AI活用PJの両輪。8/18のキックオフではこの2つの関係と、Tips配信の届け方(案A: Teams全体チャンネル投稿 vs 案B: 各部の部会でアンバサダーが紹介)を論点として提示。ユーザーは案B(部会で紹介)の方が局員との会話が増えて良いのではという仮説を持っている。

この内容をキックオフ資料に反映し、新ファイル`AI活用PJ_アンバサダーキックオフ_20260818.pptx`として保存(8/17版は上書きせず別ファイルとして残置)。スライド構成(9枚): ①タイトル②アンバサダー一覧③役割定義④ヒアリングの型⑤Salesforce記録方法⑥週次サイクル⑦プッシュ型×プル型の両輪⑧Tips配信の届け方(本日の論点、Week01サンプル付き)⑨今日決めたいこと(Tips届け方の決定を追加)。

## 2026-08-18: キックオフミーティング実施・結論
実際のキックオフ(出席: 中村正樹進行、小松瞳、満生哲平、薛倩、庄司直弘ほか各部アンバサダー)で、事前に用意した「プッシュ型 vs プル型」論点を議論した結果、**プッシュ型を基本とする方針で決着**した(案A/案Bで悩んでいた案Bのプル型寄り仮説は覆り、出席者の総意でプッシュ型優勢に)。

**決定事項:**
- ヒアリング(プル型)は反応が薄くタイムラグがあり形骸化しやすいという指摘が複数の出席者(小松さん・満生さん・薛さんなど)から出た
- 運用: 中村さんがAIチップスを用意 → まずアンバサダーへ共有 → 各部の部会で紹介 → 1週間程度の時差でTeams全体へ展開、の2段階
- Salesforce記録・案件登録は必須運用にせず、無理にルーティン化しない方針に転換(資料で説明していた「記録先はSalesforce」は事実上ペンディング/簡略化)
- 共有プラットフォームはTeams基本(部会頻度が部ごとにバラバラなため)
- 派生アイデア: 社内各所のAIチーム発ネタをクロールして再投稿する案、反応の良いチップスの簡易エージェント化・配布案

**スケジュール:** 8月は部会が夏休みで停止中のため、9月から本格始動。**2026-09-01(火)の定例会**で、中村さん・榎本さんの2人がアンバサダー向けにTipsハンズオンを実施し、そこでインプットした内容を9月の1ヶ月間かけて各部のアンバサダーがそれぞれの部会で紹介していく、という2段階運用(ユーザーが8/18終業後に訂正・確定)。
