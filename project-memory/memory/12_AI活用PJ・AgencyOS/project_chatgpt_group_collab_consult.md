2026-10-09、中村さんのスタッフから「同じ資料を元に各自ChatGPTと話しているが、互いのチャットが見えない。メンバー全員+AIのグループで議論したい」という相談があった。
調べた機能の状況: ChatGPTのグループチャットは2026-07-09から新規作成不可(段階的廃止)。電通のEnterpriseでは「共有プロジェクト」が代替になる。全員のチャット(作成者名つき)・ファイル・指示が見える。
回答: 第1案=共有プロジェクト+「決定事項ログ」ファイルの運用。第2案=社内API/ガバナンスが許せばWebアプリを自作。
**Why:** 続きの相談(Webアプリ化など)が来たときに同じ調査をやり直さないため。
**How to apply:** 続報が来たら、まず共有プロジェクトを試した結果を聞く。Enterpriseで他メンバーのチャットを続けて書き込めるかはまだ確認していない。共有するとプロジェクト専用メモリが自動でON(元に戻せない)で、同じプロジェクト内のチャットをAIが参照できる。決定事項ログへの自動保存機能はない。[[gbc_intelligence_engine_project]]

## 実機試験結果 2026-10-09（個人Mac、9229 chatgpt-work-bot、中村さんのEnterpriseアカウント1つで実施）
- 共有ダイアログの表示文:「プロジェクトのすべてのコンテンツは共同作業者に表示されます。個人データを保護するため、共有プロジェクトでは個人メモリが無効になります。」アクセス権の既定は「招待されたユーザーのみ」。
- 作成時のメモリ選択肢は「デフォルトメモリ」と「プロジェクト限定メモリ」の2つ。
- デフォルトメモリのプロジェクト: 「覚えて」と言うと**個人メモリ(gizmo_id null)に保存**され、プロジェクトの外でも答えてしまう(漏れる)。試験で入った1件は API の DELETE /backend-api/memories/{id} で削除済み。
- プロジェクト限定メモリのプロジェクト: 「覚えて」と言わない普通の議論でも、別チャットの決定事項(商品名・ターゲット・価格)をAIが拾えた。プロジェクトの外では「わからない」となり、漏れなかった。
- 「全チャットから決定事項ログを作って」と頼むと、出典チャット名つきで正確にまとまった(推測による補完はなし)。
- **まだ試していないこと**: 別のメンバーのアカウントのチャットを拾えるか(2人目のアカウントが必要)。他人のチャットに続けて書き込めるか。
- 検証用プロジェクト「【検証】共同チャットテスト」「【検証2】共同チャット専用メモリ」は、2人での試験に使うため残してある(未共有)。
- 試験用スクリプト: ~/Scripts/chatgpt_project_test/ (lib.js, chat.js: `node chat.js <プロジェクトURL> <プロンプトファイル>` でプロジェクト内に新規チャットを作り回答を出力)。
- 操作上の注意: サイドバーのボタンは `.click()` だと他の要素に遮られて時間切れになる → `evaluate(e=>e.click())` を使う。メモリのドロップダウンは focus+Enter で開く。

## 2人目のアカウントでの試験 2026-10-10
- 個人Macに個人アカウント用の専用ブラウザを新しく作った: `~/.chrome-profiles/maxakisan-bot`、CDPポート9230(会社Macの9230と同じ名前・番号にそろえた)。maxakisan@gmail.com(ChatGPT無料プラン)でログイン済み。
- 電通Enterpriseのプロジェクトの共有画面で maxakisan@gmail.com を入力→「招待」を押すと、POST /backend-api/projects/share は200を返す。しかしメンバー一覧には入らず、エラー表示もない。Gmail側から開いてもトップ画面に戻される。レスポンスの sharing_targets は private と workspace_link だけ→**社外アカウントは共有先にできない(何も表示されずに外される)**。
- このため、Gmailのアカウントでは2人での試験ができない。2人での試験は社内のメンバーに頼む必要がある。
