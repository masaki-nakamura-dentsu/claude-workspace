社内で「良い企画書」を判断できる人にインタビューし、その暗黙知(何が良い/悪いか、どうすれば良くなるか)を言語化・構造化して、最終的にAIエージェント(企画書レビューボット等)に組み込むプロジェクト。2026-08-04に着手。

**Why**: 企画書の良し悪しの判断が特定個人の暗黙知として属人化しており、若手育成が非効率なうえ、汎用LLMによる企画書レビューも組織固有の評価軸を持たないため機能しない。[[proposal_writing_framework]] は中村さん個人が把握している4フレームワーク(リボン思考/1-3-1方式/3fact+解釈/ストーリー性)だが、これは個人の理解であり、組織の審査官全体の判断基準ではない。

**進め方**:
1. デモ企画書(推奨: 出来の異なる複数パターンを相対比較させる方式)を使い、審査経験者3〜5名にパイロットインタビュー(第一印象→良い点/弱い点の具体指摘→通過/不通過の分岐点→改善アドバイス→相対比較→一言化、の順)
2. 発言を評価軸(論理性/ストーリー性/ビジュアル/独自性/実現可能性/熱量など)ごとにタグ付けして構造化
3. 評価フレームワークをLLMプロンプト/エージェントとして実装しテスト運用
